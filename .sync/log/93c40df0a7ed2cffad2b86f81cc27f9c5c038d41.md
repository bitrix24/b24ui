# port — nuxt/ui@93c40df0a7ed2cffad2b86f81cc27f9c5c038d41

**Upstream:** fix(App): apply the `dir` prop to the provided locale (#6767)

**Decision:** port.

## The defect

`B24App` passed `dir` to reka's `ConfigProvider`, but provided the locale to
the library's own components unchanged. Everything that reads direction from
`useLocale().dir` — `Pagination`'s chevrons, among others — therefore ignored
`<B24App dir="rtl">` whenever no locale was set (they stayed `ltr`), and an
explicit `dir` could not override an `rtl` locale.

`App.vue` in the fork had the identical line
(`const locale = toRef(() => props.locale)`), so the fix is upstream's:
provide `{ ...(props.locale || en), dir: props.dir }` when `dir` is set.

## Tests

Upstream's new `test/composables/useLocale.spec.ts`, adapted to `B24*`
components and to the fork's icon components (`icons.chevronDoubleRight` etc.
from `dictionary/icons` instead of `i-lucide-*` strings). On the fork's code
3 of its 7 cases went red in both projects — `follows the App dir prop without
a locale`, `lets the App dir prop override the locale dir`, and the Pagination
icon case — and all pass after the fix.

Mutation check found a gap: dropping the `|| en` fallback (so the provided
locale is `{ dir }` alone) left all seven green, while every `t()` inside such
an App would return raw keys. Added one case not in upstream's set, `keeps the
default messages when the App sets only dir`; it is red under that mutation
(`expected 'contentSearchButton.label' to be 'Search…'`) and green on the fix.
