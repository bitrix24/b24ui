needs regenerating. It has to track the installed version, and upstream's had been
stale since they moved to 4.3.2.

## Why it does not apply

**The file is already byte-identical to upstream's post-image.** Both are 31 bytes
and hash to `de10ea5df74fec0e…`, trailing-newline detail included.

`test/nuxt/.nuxtrc` was set to `4.3.2` here in `ef7d0cbd` (#579, porting
`nuxt/ui@69b075a` — `chore(deps): update non-major dependencies`). That is the same
upstream commit that moved `@nuxt/test-utils` to `^4.3.2`; upstream bumped the
dependency and left the marker, this fork moved both together. So the marker has
been correct here since #579 and there is nothing to port.

**And the value is right, not merely matching.** `package.json:221` declares
`"@nuxt/test-utils": "^4.3.2"` and `pnpm-lock.yaml` resolves `@nuxt/test-utils@4.3.2`
— read from the lockfile, not from `node_modules/.pnpm`, which keeps directories
from earlier installs. The marker names the version actually in use.
