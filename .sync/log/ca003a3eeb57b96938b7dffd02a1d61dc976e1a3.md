## Upstream change

One line in `docs/app/utils/markdown.ts`:

```ts
const parse = createMarkdownParser({ plugins: markdownPlugins, autoClose: false })
```

with the reason in a comment: nothing that parser handles streams, and comark
0.7's healing — which closes an unfinished document — adds a stray backtick after
a double-backtick span carrying attributes.

## Why it does not apply

**The file does not exist here.** `docs/app/utils/markdown.ts` arrived in
`6b4d2c72`, the docs navigation rework recorded as n/a one commit ago, and
`createMarkdownParser` appears nowhere in this tree.

**Our own comark usage is the opposite case.** We do depend on `@comark/vue`
(`docs/package.json`, `^0.7.0` since #579) and use it in three places — the two
chat-palette examples and the sidebar chat example. All three render through the
`Markdown` component, and all three pass `:streaming="isPartStreaming(part)"`:
they display streaming AI output, which is exactly what auto-close is for.
Turning it off there would be the wrong change, not the same one.

**And the option is not reachable through our door anyway.** `Markdown.js:77`
calls `parse(markdown.value, { streaming: props.streaming })` — `autoClose` is
never forwarded, and comark's `parse` defaults it to `true`. So there is no
`autoClose: false` to pass even if it were wanted.

**The bug pattern is absent.** A grep for a double-backtick span with attributes
across `docs/content` and `docs/app` finds nothing.

## A trap worth recording

The first read of the installed package reported `@comark/vue@0.6.2`, which would
have made the whole question moot — the bug is a 0.7 behaviour. That was
`node_modules/.pnpm` keeping a directory from an earlier install: the store holds
both `0.6.2` and `0.7.0`, and only the lockfile says which one is resolved
(`0.7.0`). The same trap is recorded against `@nuxtjs/mdc` in an earlier entry,
and it caught this one too — read `pnpm-lock.yaml`, never the store.
