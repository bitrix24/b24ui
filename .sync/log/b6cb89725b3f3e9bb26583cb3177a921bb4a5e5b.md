# port — nuxt/ui@b6cb89725b3f3e9bb26583cb3177a921bb4a5e5b

**Upstream:** refactor(unplugin): resolve vue runtime paths from a file url

**Decision:** port — this is the second half of `b0e1d715` and repairs a real
cross-platform defect that half introduced.

## The defect

`b0e1d715` (#604 here) moved four `resolvePathSync` calls onto an absolute path
anchored on `runtimeDir`. `resolvePathSync` resolves its first argument as a URL
against the `url` option — and an absolute **Windows** path is not a path to a URL
parser, it is a scheme.

Reproduced by parsing, since CI is ubuntu:

```
base     : D:/app/node_modules/@bitrix24/b24ui-nuxt/dist/runtime/
protocol : d:            <-- a custom url scheme, not a path
resolves : d:/app/.../dist/runtime/vue/plugins/head
```

`D:` is read as the scheme, so the "path" that comes out is a `d:` URL. On a
Windows checkout the Vue adapter would fail to resolve its own runtime plugins.

## The fix

`src/unplugin.ts` exports a `runtimeUrl` beside `runtimeDir`:

```ts
// `resolvePathSync` needs a relative id and a file url: an absolute Windows path like `D:/...` is parsed as a `d:` url scheme
export const runtimeUrl = pathToFileURL(`${runtimeDir}/`).href
```

and the four call sites go back to a **relative** id resolved against it:

```diff
-resolvePathSync(join(runtimeDir, 'vue/plugins/router'), { extensions: […] })
+resolvePathSync('./vue/plugins/router', { extensions: […], url: runtimeUrl })
```

With a real file URL as the base the scheme is `file:` and the result is a proper
file URL. This keeps everything `b0e1d715` was for — the anchor is still
`runtimeDir`, not `import.meta.url`, so a bundled file still cannot mis-resolve by
landing in a different chunk.

`join` becomes unused in `bitrix24-environment.ts` and its import is dropped;
`plugins.ts` keeps it, since `globSync`'s `cwd` still uses it. Upstream's files
end in exactly that state.

## The trailing slash is load-bearing

`pathToFileURL(`${runtimeDir}/`)` — with the slash. Demonstrated on posix, where
the comparison is exact:

```
with    / : file:///x/dist/runtime/vue/plugins/head
without   : file:///x/dist/vue/plugins/head
```

Without it the base names a *file*, so `./vue/...` resolves as a sibling of
`runtime` rather than inside it, and every plugin path is silently wrong by one
directory. Nothing in the commit says so; it is worth knowing before someone
"tidies" the template literal.

## Evidence

**The value is checked against the build, not the source.** Importing the built
`dist/unplugin.mjs`:

```
runtimeDir: /home/user/b24ui/dist/runtime
runtimeUrl: file:///home/user/b24ui/dist/runtime/
```

**And the sites are live.** The same mutation used in #604 — pointing one at a
name that does not exist — still fails `dev:vue:build`, so these lines are
resolved at build time rather than being dead configuration.
