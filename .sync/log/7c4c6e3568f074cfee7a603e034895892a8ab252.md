# port — nuxt/ui@7c4c6e3568f074cfee7a603e034895892a8ab252

**Upstream:** fix(DashboardNavbar): render title only when defined (#6958)

**Decision:** port — the same defect is here, in the same line, and the fix
transfers with nothing but the `ui` → `b24ui` rename.

## The defect

`DashboardNavbar` rendered its `<h1 data-slot="title">` unconditionally. With no
`title` prop and no `title` slot the markup still carried an empty heading:

```html
<h1 data-slot="title" class="… font-medium … truncate"></h1>
```

An empty `<h1>` is not only dead markup — it is a heading with no accessible name
in the document outline.

## Upstream fix

```diff
-<h1 data-slot="title" :class="ui.title({ class: props.ui?.title })">
+<h1 v-if="props.title || !!slots.title" data-slot="title" :class="ui.title({ class: props.ui?.title })">
```

plus one test and the snapshot churn.

## Applicability

Ours at `src/runtime/components/DashboardNavbar.vue:109` was line-for-line
upstream's pre-image modulo the rename, so the hunk applies directly:

```diff
-<h1 data-slot="title" :class="b24ui.title({ class: props.b24ui?.title })">
+<h1 v-if="props.title || !!slots.title" data-slot="title" :class="b24ui.title({ class: props.b24ui?.title })">
```

Three things were checked rather than assumed:

- **`slots` is in scope** — `defineSlots<DashboardNavbarSlots>()` at line 69, and
  the same `!!slots.X` idiom is already used ten lines below at
  `v-if="!!slots.default"`. Nothing new is introduced.
- **`title` has no default.** `withDefaults` sets only `toggle` and `toggleSide`,
  so `props.title` is `undefined` when unset and the guard behaves as upstream's.
- **`props`, not `_props`.** This fork wraps props in
  `useComponentProps('dashboardNavbar', _props)`, so a `title` supplied through
  `<B24Theme :props>` or `app.config` appears on `props` and not on the raw
  `defineProps` result. Reading `props.title` is both correct and what
  `bitrix24-ui/no-bare-prop-refs` requires.

## Test

Upstream's new test, in this fork's spec idiom:

```ts
it('does not render the title without title', async () => {
  const wrapper = await mountSuspended(DashboardWrapper)

  expect(wrapper.find('[data-slot="title"]').exists()).toBe(false)
})
```

## Mutations

Each half of `props.title || !!slots.title` is independently covered:

| mutation | result |
| --- | --- |
| `v-if="!!slots.title"` — prop half dropped | `renders with title correctly` fails, both environments |
| `v-if="props.title"` — slot half dropped | `renders with title slot correctly` fails, both environments |
| guard removed entirely | `does not render the title without title` fails, plus 24 snapshots |

Worth recording how this nearly went wrong: the first mutation run used `sed` with
`|` as both the delimiter and part of the pattern (`||`). All three substitutions
failed with `unknown option to 's'`, the file was never modified, and all three
runs reported `34 passed` — which reads exactly like "the mutations were caught by
nothing". Re-run through Python, the real results are above. A mutation that
reports green because it never applied is the worst possible outcome, since it
looks like evidence.
