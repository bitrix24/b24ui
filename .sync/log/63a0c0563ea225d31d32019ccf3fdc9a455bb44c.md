# Port: feat(CheckboxGroup): add `max` prop (#7145)

**Upstream:** `63a0c0563ea225d31d32019ccf3fdc9a455bb44c` (nuxt/ui)
**Decision:** port
**Depends on:** the reka-ui 2.11.0 bump (`fa7a930`). `max` on `CheckboxGroupRootProps`
and `max: Ref<number | null | undefined>` on the group root context are new in reka-ui
2.11.0, which uses them to put `aria-disabled` (but not `disabled` or `data-disabled`)
on the unchecked checkboxes once the limit is reached. On 2.10.5 this does not
typecheck.

## Upstream change
- `CheckboxGroup.vue`: `'max'` is added to the `CheckboxGroupRootProps` pick and to the
  `reactivePick` forwarded to `CheckboxGroupRoot`.
- `Checkbox.vue`: reads `injectCheckboxGroupRootContext(null)` and computes
  `maxReached`. That is true when the group's `max` is set, the number of checked
  values is at or above it, and this checkbox's value (Reka's default is `'on'`) is not
  among them, compared with `isEqual` from `ohash/utils`. It is OR-ed into the theme's
  `disabled` variant only. `CheckboxRoot` still gets the plain `disabled`, so blocked
  items stay focusable, as Reka intends.
- `checkbox-group.ts`: the `table` item gets `has-aria-disabled:cursor-not-allowed`.
  The group's `disabled` compound doesn't know about `max`, so it can't add the cursor
  itself.
- `checkbox.ts`: the shared `hover` prefix and the `highlight` + `indicator: hidden`
  border compounds gain `not-has-aria-disabled:`, so blocked items get no hover or
  highlight border.
- `CheckboxGroup.spec.ts`: two render cases, `with max` and `with max variant table`.
  Also a test that a checked item without a value (`'on'`) or with a `null` value stays
  enabled while the other item gets the disabled opacity.
- `checkbox-group.md`: a new "Max" section with a Soon badge.
- Snapshots: the Checkbox and RadioGroup snapshots change because of the `hover`
  prefix. In CheckboxGroup the same prefix changes, the table item class changes and
  the two new entries are added.

## b24ui port
- `src/runtime/components/Checkbox.vue`, `src/runtime/components/CheckboxGroup.vue`:
  the same code as upstream. The theme computed is `b24ui`, so `maxReached` feeds its
  `disabled` variant. `ohash` is already a dependency (`Link.vue` and `InputMenu.vue`
  import `isEqual` from `ohash/utils`).
- `src/theme/checkbox-group.ts`: `has-aria-disabled:cursor-not-allowed` added to the
  fork's `table` item list, after `cursor-pointer`.
- `src/theme/checkbox.ts`: not changed. The fork's checkbox theme has no `hover`
  prefix (the export that `radio-group` and `checkbox-group` use upstream). It also has
  no `highlight` + `indicator: hidden` border compounds, so the classes upstream
  extends do not exist here. A blocked item gets the fork's `disabled` variant
  (`opacity-30` on the root, `cursor-not-allowed` on base, label and description, and
  the `card` + `disabled` cursor compound).
- `test/components/CheckboxGroup.spec.ts`: upstream's cases. The opacity assertions use
  the fork's disabled class, `opacity-30` (upstream uses `opacity-75`).
- `docs/content/docs/2.components/checkbox-group.md`: the section is the last usage
  section, after "Disabled" as upstream has it. In the fork that puts it before
  "Examples" (upstream has no Examples section).
- Snapshots: regenerated with `vitest run -u`. Checkbox and RadioGroup are expected
  to stay unchanged, because the fork has no shared `hover` prefix. In CheckboxGroup the
  `table` variant entries gain `has-aria-disabled:cursor-not-allowed` on the items, and
  `with max` and `with max variant table` are new. In those two, options 2 and 3 render
  with `aria-disabled="true"` and the disabled variant classes.
