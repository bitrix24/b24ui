# Port: chore(deps): update nuxt framework

**Upstream:** `282759e7c6b6df3d9ae842df7f379f9f8f9298b4` (nuxt/ui, #6751)
**Decision:** port — major framework bump + accompanying source/test fixes

## Upstream change
Renovate bump of the Nuxt framework with the source changes needed to survive it:
- `nuxt` / `@nuxt/kit` / `@nuxt/schema` `^4.4.8` → `^4.5.1`,
  `@unhead/vue` `^2.1.16` → `^3.2.3` (major), `magic-string` `^0.30.21` → `^1.1.0`
  (major), `vite` `^7.3.6` → `^8.1.5` in the playgrounds.
- `pnpm-workspace.yaml`: `@nuxt/kit` override `^4.4.8` → `^4.5.1`.
- `vitest.config.ts`: the `#components` virtual-module plugin now returns a
  `\0`-prefixed id — Vite 8 rewrites a returned `#components` to
  `?import#components` (empty pathname) which its builtin resolver rejects.
- `test/utils/setup.ts`: stub `fetch` so `@iconify/vue` icon requests resolve
  instantly (vitest 4 surfaces happy-dom's teardown abort as an unhandled error).
- `test/components/FormField.spec.ts`: hoist `vi.mock('vue')` to the module top
  level (it is hoisted anyway; nesting it misrepresents execution order).
- `src/components/content/ContentNavigation.vue` (absent in b24ui).

## b24ui port
- **Manifests** — same bumps: `@nuxt/kit`, `@nuxt/schema`, `nuxt`, `@unhead/vue`
  v3, `magic-string` v1 in `package.json`; `nuxt` in `docs`, `playgrounds/nuxt`
  and **`playgrounds/demo`** (b24ui-only workspace — leaving it at 4.4.8
  duplicated nuxt in the tree); `vite` `^8.1.5` in `playgrounds/{repl,vue}`.
- **`pnpm-workspace.yaml`** —
  - `@nuxt/kit` override `^4.4.8` → `^4.5.1` (as upstream). The 4.4.8 kit has no
    `buildDiagnostics` export, which nuxt 4.5.1's CLI imports → `dev:prepare` died.
  - corrected the stale `@tiptap/pm` override `^3.27.3` → `^3.29.0` left behind
    by PR #298.
  - **fork-specific:** `vite: ^8.1.5` + `rolldown: ~1.1.5` overrides. b24ui's
    dependency set (unplugin/unhead/vite-plugin-* peers, plus the legacy
    `vitest-environment-nuxt` that upstream doesn't carry) otherwise resolves
    **two** vite copies (7.3.6 + 8.1.5) and two rolldown copies (1.1.5 + 1.2.0).
    Loading both native ABIs in one worker made every nuxt-project test file
    fail at startup with ``Missing field `moduleType` `` (plugin
    `builtin:replace`, rolldown 1.2.0 running inside vite 7.3.6). vite 8 pins
    rolldown `~1.1.5`, so `~1.1.5` satisfies both it and unplugin (`*`).
- **`vitest.config.ts`** — applied the Vite 8 virtual-module fix, using
  `\0virtual:bitrix24-ui-components` for b24ui's `bitrix24-ui-test:components`
  plugin.
- **`test/components/FormField.spec.ts`** — hoisted `vi.mock('vue')` to the top
  level (b24ui had the same nested call and the same vitest warning).
- **`src/runtime/plugins/colors.ts`** — unhead v3 removed the `UseHeadInput`
  type (now `ReactiveHead`), which broke `typecheck`. Typed `headData` as
  `Parameters<typeof useHead>[0]` so it stays correct on both v2 and v3, and
  dropped the now-unused `@unhead/vue/types` import. The file's existing
  v2/v3 `hooks.hook` compat shim is untouched.

### Skipped
