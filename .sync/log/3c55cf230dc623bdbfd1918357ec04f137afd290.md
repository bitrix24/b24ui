# port — nuxt/ui@3c55cf230dc623bdbfd1918357ec04f137afd290

**Upstream:** fix(ContentSearch/DashboardSearch): use translated search label as dialog title (#7062)

**Decision:** port.

## The defect, in this fork

Both components titled their modal `t('contentSearch.title')` /
`t('dashboardSearch.title')` and described it with the matching
`.description` key. Those keys are optional in the `Messages` type and **no
locale in `src/runtime/locale/` defines them**, and `translate()` returns the
path itself when a key is missing. So the dialog's accessible name was the
literal string `contentSearch.title` / `dashboardSearch.title` — read aloud by
screen readers — and the committed snapshots already contained it (14
`dashboardSearch.title` and 15 `contentSearch.title` occurrences).

## Fix

Upstream's: title falls back to the locale's own `…Search.title` if present,
else to the translated button label (`contentSearchButton.label` /
`dashboardSearchButton.label`, "Search…" in `en`); description is the locale's
`…Search.description` or nothing. The fork's `Modal` handles a missing
description the same way upstream's does (an empty visually-hidden
`DialogDescription`).

## Tests

Upstream's `labels the dialog with the translated search label` added to
`ContentSearch.spec.ts`, and the same case added to `DashboardSearch.spec.ts`
(upstream changed both components but tested one). All three runs were red on
the fork's code with `expected 'contentSearch.title' / 'dashboardSearch.title'
to be 'Search…'` and green after. Snapshots regenerated with the whole suite.
