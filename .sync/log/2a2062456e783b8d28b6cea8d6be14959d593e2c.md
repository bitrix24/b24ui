## `testing.md` — not taken

**Snapshot-update hunk: skipped.** Upstream now writes
`pnpm run test run -u <spec>` — "on the affected specs only". This fork's
`testing.md` says the opposite, *"the whole suite, never a subset"*, and
documents why: on the pinned vitest, `-u` swallows the next token as its value,
so the path stops being a filter and the whole project runs.

That was re-measured rather than trusted, since vitest has moved since the note
was written (#625). On vitest **4.1.11**, on a clean tree:

```
vitest run -u test/components/Kbd.spec.ts --project nuxt   →  Test Files  185 passed (185)
vitest run test/components/Kbd.spec.ts -u --project nuxt   →  Test Files  1 passed (1)
```

Upstream's spelling is the first one. Porting it would teach contributors to
rewrite snapshots across the whole project while believing they touched one.
Zero snapshot files changed during the measurement (clean tree, `git status`
confirmed).

**Coverage hunk: already handled.** Upstream deletes `pnpm run test --
--coverage`. This fork replaced that line long ago with `pnpm run test:coverage`
and a Coverage section explaining why it only works as a whole run.
