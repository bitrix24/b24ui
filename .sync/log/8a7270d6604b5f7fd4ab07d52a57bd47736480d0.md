# Port: fix(useTour): accept any CSS selector as step target (#7144)

**Upstream:** `8a7270d6604b5f7fd4ab07d52a57bd47736480d0` (nuxt/ui)
**Decision:** port

## Upstream change
`useTour` resolved a string `target` as follows: a string starting with `#` or `.` went
to `querySelector` as-is, and anything else got `#` prefixed. So an attribute or
compound selector such as `'[data-tour="step"]'` or `'button.cta'` became an invalid id
selector, matched nothing, and left the step unanchored.

Now:
- A plain word (`/^[\w-]+$/`) is resolved with `document.getElementById`. A bare
  `'header'` still means `#header` and never the `<header>` tag, and the lookup works
  for ids that are not valid CSS identifiers.
- Any other string goes to `querySelector` unchanged. The existing `try/catch` still
  turns a malformed selector into `undefined`.
- The `TourStep.target` jsDoc and the two descriptions in `use-tour.md` now describe
  the bare-id rule and "any CSS selector".
- `useTour.spec.ts` gets four new cases: an attribute selector, a bare id winning over
  a same-named tag, a plain word matching no id staying `undefined` (no fall back to
  the tag), and `'#cta'` not being read as a literal id `#cta`.
