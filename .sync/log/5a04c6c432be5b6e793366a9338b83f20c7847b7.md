# port — nuxt/ui@5a04c6c432be5b6e793366a9338b83f20c7847b7

**Upstream:** fix(theme): drop double quotes from class strings (#7039)

**Decision:** port — upstream's two lines are n/a here, the same defect exists
in four fork-only lines, and those are fixed.

## The defect, measured

Theme files are serialized into `.nuxt/b24ui/*.ts` with `JSON.stringify`
(`src/templates.ts`). A class containing `"` is therefore written as `\"`.
Tailwind's scanner reads that generated file and extracts the candidate with
the backslashes in it, so the rule it emits has a class selector that matches
no element — the class is on the element, in every snapshot, and the style
never applies.

The docs site masked it: `docs/app/assets/css/main.css` also `@source`s
`src/`, where the unescaped spelling lives, so the docs build got a correct
rule from there. `dist/` ships only the generated form, so a consumer app got
only the broken rule.

## b24ui adaptation

Upstream's hunks are n/a:

- `src/theme/input-tags.ts` — the fork's `item` slot has no
  `data-[state="active"]` class;
- `src/theme/marquee.ts` — the fork has no Marquee component or theme.

A sweep of `src/theme/` for `"` inside class strings found four instead, all
fork-only `bitrix-mobile:` rules in the menu themes:

| File | Slot | Before | After |
|---|---|---|---|
| `context-menu.ts` | `label` | `[&_[data-slot="itemLabel"]]` | `[&_[data-slot=itemLabel]]` |
| `context-menu.ts` | `item` | `[[data-slot="item"]+&]` | `[[data-slot=item]+&]` |
| `dropdown-menu.ts` | `label` | `[&_[data-slot="itemLabel"]]` | `[&_[data-slot=itemLabel]]` |
| `dropdown-menu.ts` | `item` | `[[data-slot="item"]+&]` | `[[data-slot=item]+&]` |

So in consumer builds on Bitrix24 mobile, menu section labels kept the default
colour instead of `--ui-color-base-5`, and adjacent menu items had no top
divider. The attribute values are plain identifiers, so dropping the quotes is
valid CSS with the same meaning.

Compiled with the installed `tailwindcss@4.3.3` and the fork's
`bitrix-mobile` variant, the unquoted candidates produce
`:where(html[data-platform="bitrix-mobile"] *) [data-slot=itemLabel] { color: var(--ui-color-base-5) }`
and `[data-slot=item] + .…:where(…) { border-top-width: 1px }` — rules that
match the rendered class.

## Guard

`test/utils/theme-no-escaped-quotes.spec.ts` renders every theme template
(`getTemplates` with prose and content on) exactly as the module writes it and
fails on any `\"`. Red before the fix with exactly the four lines above, green
after. It checks the generated text, not the sources, because that is what the
scanner reads; a floor assertion keeps the template list from silently
emptying.
