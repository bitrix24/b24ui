# port — nuxt/ui@e8756fd3a8aaab3cb434f1dfe8d32559330f38a9

**Upstream:** fix(Table): keep footer separator above pinned columns (#7047)

**Decision:** port.

## The defect

The table draws its header/footer divider as an absolutely positioned
`<tr data-slot="separator">` with `z-1`. Pinned cells (`pinned: true` on `th`
/ `td`) are `sticky` with the same `z-1` and an opaque background.

At equal `z-index` the element later in the DOM paints on top. In `thead` the
separator follows the header row, so it wins. In `tfoot` it is the **first**
child, before the footer row, so pinned footer cells paint over it and the line
has gaps exactly where columns are pinned.

## b24ui adaptation

The fork has the same structure, measured rather than assumed:
`src/theme/table.ts` has `separator: 'absolute z-1 …'`, `pinned.true.th/td`
are `sticky … z-1`, and `Table.vue` renders the `tfoot` separator before the
footer rows. Only the colours and the multi-line layout of the slot strings
differ.

The fork's `tfoot` slot was plain `'relative'` like upstream's, so the change
is the same one line: `'relative [&>[data-slot=separator]]:z-2'`. Compiled with
the installed `tailwindcss@4.3.3`, the class emits
`.… > [data-slot=separator] { z-index: 2 }`.

## Tests

Upstream's case `with column pinning and footer` added to
`test/components/Table.spec.ts` (the fork's `columns` has an `amount` footer,
an `id` accessor and an `actions` column, so both pins land). Its snapshot was
written on the fork's code first; applying the theme change turns that case red
in both projects, so the snapshot covers the new class. Snapshots then
regenerated with the whole suite.

What a snapshot cannot show is the stacking itself — happy-dom computes no
layout — so the painting order above is argued from the DOM and the compiled
rule, not observed.
