## Why it does not apply

**Seven of the 11 files do not exist here**, and they are the whole substance:
all three `og-image/*.takumi.vue` components, both banner PNGs, `.github/assets/`
as a directory, `docs/public/og-image.png` and `docs/public/theme/og-image.png`.
A repo-wide `find` for `og-image*` (excluding `node_modules` and `.git`) returns
nothing.

**The stack they belong to was removed on purpose.** `nuxt-og-image`,
`@takumi-rs/core`, `defineOgImage` and the `ogImage` config block appear nowhere
in this tree — a grep across `.ts`, `.vue`, `.json` and `.yml` hits only
`.sync/nuxt-ui.json`, describing the removal. That ledger entry records it
directly: b24ui #324 (`3faa2e4`, *drop the dead og-image stack*) took out the
manifests, the `pnpm-workspace` pin, both `*.takumi.vue` components, the
commented-out `defineOgImage` calls and the `docs/nuxt.config.ts` block, closing
issue #321 — and concludes that upstream bumps to `nuxt-og-image` and
`@takumi-rs/core` are "N/A by absence". This commit is the next instance of
exactly that. (`3faa2e4` itself is not readable from here: the working clone is
shallow at 155 commits, oldest 2026-08-15, and that commit is from 2026-08-06.
The current tree is the evidence, and it is unambiguous.)

**`@nuxt/fonts` is not a module here either**, so part 2 has nothing to attach to.
`docs/nuxt.config.ts` lists `../src/module`, `./modules/bx-assistant`,
`@nuxt/content`, `@nuxtjs/mcp-toolkit`, `nuxt-component-meta`, `nuxt-llms`,
`motion-v/nuxt` and `nuxt-schema-org` — no fonts module, no og-image module.

**The README has no banner to move.** `README.md` opens with `# Bitrix24 UI` and
four badges; there is no `<picture>` element, and nothing points at
`user-attachments`.

**The landing copy is ours.** `docs/content/index.yml` has `title` and
`description` under `hero`, not `lead`/`accent`/`breakLine`. The capitalisation
fix is to a field this fork does not have.

## The one part that looks portable is already done

Dropping `ogImage: joinURL(url, '/og-image.png')` from `useSeoMeta` is the only
hunk whose target file both exists here and is structurally similar. It is
already the state of `docs/app/pages/index.vue`: `useSeoMeta` carries
`titleTemplate`, `title`, `description`, `ogTitle` and `ogDescription` and no
`ogImage`, `useSiteConfig` is not called, and the `joinURL` import sits commented
out on line 2 — a leftover from the same #324 removal. Upstream is arriving at
the state this fork has held since then.
