## Upstream change

`ChatMessages` lets a caller set defaults for every user or assistant message
through two `Pick<>`s of `ChatMessage`'s own props. `color` was missing from both
lists, so it could be set per message but not for the whole side — an omission
rather than a decision, the neighbouring `variant` and `side` being there.

```diff
-  user?: Pick<PropsBase<T>, 'icon' | 'avatar' | 'variant' | 'side' | 'actions' | 'ui'>
+  user?: Pick<PropsBase<T>, 'icon' | 'avatar' | 'variant' | 'side' | 'actions' | 'ui' | 'color'>
```

## b24ui port

Applies verbatim, two lines, with the standing `ui` → `b24ui` rename in the
picked key list (§1). Our pre-image is upstream's otherwise character for
character at `ChatMessages.vue:54` and `:59`.

Checked rather than assumed that the key exists to pick: `ChatMessage.vue:34`
declares `color?: ChatMessage['variants']['color']`. A `Pick<>` of a key the
source type does not have is a type error, so this would not have survived
`typecheck` — but the point of looking was that it *could* have been a prop this
fork dropped, in which case the right answer would have been a no-op rather than
a port.

No render changes and no snapshots move: this widens a type, and nothing in the
suite passes `color` through `user` or `assistant`.
