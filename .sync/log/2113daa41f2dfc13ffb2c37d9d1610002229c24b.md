# Port: feat(Sidebar): add `breakpoint` prop (#7155)

**Upstream:** `2113daa41f2dfc13ffb2c37d9d1610002229c24b` (nuxt/ui)
**Decision:** port

## Upstream change
Sidebar switched to its mobile menu below `lg`, and that was fixed in two places: the
theme (`lg:flex` / `lg:block`) and the component (`useMediaQuery('(max-width: 1023px)')`).
Upstream makes the breakpoint a prop:
- `Sidebar.vue`: new `breakpoint?: Sidebar['variants']['breakpoint']` prop (default
  `'lg'`). The media query is now built from a rem table (`sm` 40, `md` 48, `lg` 64,
  `xl` 80, `2xl` 96) as `(min-width: …rem)`, so `isMobile` is now its negation.
  `breakpoint` is passed to `tv()`.
- `sidebar.ts`: `lg:flex` is removed from the `container` and `rail` slot bases, and
  `lg:block` from the `offcanvas` / `icon` roots. A new `breakpoint` variant adds
  `<bp>:flex` to `container` and `rail`. Five compound variants
  (`breakpoint` × `collapsible: ['offcanvas', 'icon']`) add `<bp>:block` to `root`.
- `sidebar.md`: new "Breakpoint" section with a Soon badge, before "Mode".
- `Sidebar.spec.ts`: one render case per breakpoint key.
- `docs/app/components/chat/Chat.vue`: the docs site's own AI panel gets
  `breakpoint="xl"`.

## b24ui port
- `src/runtime/components/Sidebar.vue`: all four hunks, verbatim. The fork already
  reads `props` through `useComponentProps`, and the `tv()` call is the fork's
  `appConfig.b24ui?.sidebar` form.
- `src/theme/sidebar.ts`: same changes, applied to the fork's own strings. The rail
  base keeps its fork color (`hover:after:bg-(--ui-color-divider-accent)`) and only
  drops `lg:flex`. The `breakpoint` variant goes after `transition`, as upstream has
  it. The five compound variants go at the top of `compoundVariants`.
- `test/components/Sidebar.spec.ts`: upstream's two lines, verbatim.
- `docs/content/docs/2.components/sidebar.md`: the section is placed before "Mode", as
  upstream has it, with `USidebar` changed to `B24Sidebar`.
- Not ported: `docs/app/components/chat/Chat.vue`. The fork's docs have no such panel.
- Not added: a playground control. Upstream adds none, and the fork's sidebar
  playground pages only switch `variant`.
- The fork sets no custom `--breakpoint-*` values, so the rem table matches the
  Tailwind variants used in the theme.

## Tests
Five new cases, `with breakpoint sm|md|lg|xl|2xl`. In happy-dom's default 1024px
viewport, `sm` / `md` / `lg` render expanded and `xl` / `2xl` render collapsed (the
mobile menu), as in upstream's snapshots.

Expected snapshot changes, in both `Sidebar.spec.ts.snap` and
`Sidebar-vue.spec.ts.snap`:
- five new entries;
- every existing entry that renders the collapsible layout changes class order only:
  `lg:flex` on `container` (and on `rail` in `with rail`) now comes after the
  `transition` classes instead of in the slot base.
