# port — nuxt/ui@da3fd118f64cda442e0d0935e72ef253230cba5c

**Upstream:** docs(theme): note layer merging breaks function slot overrides (#6929)

**Decision:** port — the page exists here, the mechanism is Nuxt's rather than
upstream's, and it applies to this fork identically.

## Upstream change

Seven lines in `docs/content/docs/1.getting-started/5.theme/3.components.md`: a
`::framework-only #nuxt` warning that a slot may be set to a function in only one
place, because Nuxt merges every layer's `app.config.ts` with `defuFn`, which
calls the function with the value already present lower down and keeps only the
result — after which the library reads a plain string and merges rather than
replaces.

## Verified rather than repeated

The warning makes a claim about **Nuxt**, not about the library, so it was
checked in Nuxt's own output rather than carried across on trust. The generated
app-config module in `nuxt@4.5.2` is literally

```js
export default /*@__PURE__*/ defuFn(cfg0, cfg1, …, inlineConfig)
```

— one `cfgN` per layer. The claim is accurate.

It applies here for the same reason it applies upstream: components read the
merged result (`appConfig.b24ui?.…`), so whatever Nuxt's layer merge produced is
what they see. Nothing in this fork intercepts it.

## b24ui adaptation

"Nuxt UI" → "Bitrix24 UI". Everything else transfers verbatim, including the
`framework-only #nuxt` wrapper — layers are a Nuxt concept, and the Vue adapter
configures the theme through `vite.config.ts` with no layer merge at all.

## Placement

Upstream inserts before the `theme.unstyled` tip in the **Global config**
section. This fork's page has that tip **twice** — once in Global config
(line 313) and once in the `b24ui` prop section (line 367) — so the position was
chosen rather than matched by string: the warning is about `app.config.ts`, and
the `b24ui` prop has no layer merging to warn about. It sits after this fork's
own `::warning` about where a replacer takes effect, which is the same subject.
