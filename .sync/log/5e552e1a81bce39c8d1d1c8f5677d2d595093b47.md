# Port: chore(components): clean up imports

**Upstream:** `5e552e1a81bce39c8d1d1c8f5677d2d595093b47` (nuxt/ui)
**Decision:** port — two of four hunks; the other two have nothing to remove

## Upstream change
Four import tidy-ups across four components:

1. `InputDate.vue` — drop a dead `import { } from 'reka-ui'`;
2. `Popover.vue` — same;
3. `Listbox.vue` — move `import { computed, toRaw, toRef } from 'vue'` out of the
   plain `<script lang="ts">` block into `<script setup>`;
4. `Theme.vue` — same for `computed`, `defu` and the two theme-context
   composables, leaving only `import type { VNode }` in the shared block.

The point of 3 and 4 is that a plain `<script>` block and `<script setup>`
compile into different scopes: values only `setup` uses do not belong in the
block that also carries the exported interfaces.

## b24ui port

**Hunks 1 and 2 — nothing to remove.** b24ui carries no empty `reka-ui`
import; grep for `import { } from 'reka-ui'` across `src/runtime/components/`
returns nothing, so `InputDate.vue` and `Popover.vue` are already in the state
the commit produces.

**Hunks 3 and 4 apply**, and both files carried the defect:

- `Listbox.vue:4` had the `vue` runtime import in the shared block;
- `Theme.vue:3-5` had `computed`, `defu` and
  `injectThemeContext`/`provideThemeContext` there.

Checked before moving, rather than trusting the shape: neither shared block
*uses* any of those bindings. `awk`-ing each `<script lang="ts">` block and
grepping for the identifiers returns only the import lines themselves, so the
move cannot break a reference. b24ui's `Theme.vue` already had
`import type { VNode }` on its own line, so that half of upstream's hunk was
already done.
