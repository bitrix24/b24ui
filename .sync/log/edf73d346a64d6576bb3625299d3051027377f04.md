## b24ui port

nothing.

assignment anywhere, so `!event.relatedTarget || completed.value` could only
ever be decided by its left half. Both lines removed. `ref` stays imported;
`inputsRef` still uses it.

**InferInput.** Same three-branch chain here:

```diff
 export type InferInput<Schema> = Schema extends StandardSchemaV1 ? StandardSchemaV1.InferInput<Schema>
   : Schema extends SuperstructSchema<infer I, any> ? I
-    : Schema extends StandardSchemaV1 ? StandardSchemaV1.InferInput<Schema>
-      : never
+    : never
```

The third test is the first test. `InferOutput` directly below already has the
two-branch shape, which is what made the duplication visible.

**`compoundVariants: []`.** Upstream had one. This fork has **three** —
`color-picker.ts`, `description-list.ts` and `listbox.ts`. All removed; an empty
array is what `tv` defaults to.

**PricingTable.** N/A — no `PricingTable` here, and a grep for `defeault` and
the neighbouring typos across `src/`, `docs/` and `playgrounds/` returns nothing.

## Tests

No new spec. Nothing here is behaviour that can regress silently: three of the
four are deletions the type checker already covers, and the fourth (`completed`)

`DescriptionList` and `Listbox` — 288 tests — pass unchanged, including every
snapshot, which is the point: removing the empty `compoundVariants` and the cast
must produce byte-identical output.
