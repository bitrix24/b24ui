**Upstream:** docs: keep colour swatches in dark mode code blocks (#7080)

**Decision:** n/a.

Two halves, both in upstream's docs code-block pipeline:

1. `main.css`: upstream's `html.dark .shiki span:not(...)` rule forces every
   token to `--shiki-dark` colours, and swatches rendered through the content
   pipeline (a generated class, not an inline style) were caught by it and lost
   their background. The fix tags swatch spans with `shiki-color-highlight`
   (a small transformer in `docs/app/utils/shiki.ts`) and excludes them.
2. `shiki.ts`: only literal colour values get a swatch, since a bare name there
   is a Tailwind palette (`primary: violet`), not the CSS keyword.

The fork's docs have neither file: no `docs/app/utils/shiki.ts` (its
`mdc.config.ts` registers `transformerColorHighlight()` directly) and no
`html.dark .shiki` override in `docs/app/assets/css/`, so swatches are never
repainted in dark mode and there is no rule to exempt them from. The bare-name
case does not arise either: the fork's colour config uses `air-*` tokens, and
no code block in `docs/content` assigns a bare palette name.
