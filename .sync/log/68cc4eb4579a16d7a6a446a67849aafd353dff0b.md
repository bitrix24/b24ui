## Upstream change

`scripts/vercel.sh` — Vercel's *ignored build step*, which Vercel runs to decide
whether to build a commit at all. The hard-coded branch list becomes a pattern,
and the check now also requires that the build be a preview:

```diff
-if [[ "$VERCEL_GIT_COMMIT_REF" == "v2" || "$VERCEL_GIT_COMMIT_REF" == "v3"  ]] ; then
+if [[ "$VERCEL_ENV" != "production" && "$VERCEL_GIT_COMMIT_REF" =~ ^v[0-9]+$ ]] ; then
```

with the reason in a new comment: each release branch is the *production* branch
of its own Vercel project, so it should not also be built as a preview of another
project. This is the same `v5` groundwork as `2aa1702a` two commits earlier.

## Why it does not apply

**`scripts/vercel.sh` does not exist.** `scripts/` holds
`indistinguishable-snapshots.mjs`, `lib`, `regen-indistinguishable-baseline.mjs`
and `sync-skill-manifest.mjs`.

**There is no Vercel deployment.** The docs site ships through
`.github/workflows/deploy.yml` — *Deploy to Pages 📰* — to GitHub Pages, which has
no per-branch preview projects and no ignored-build-step hook to write.

**And there are no `v<N>` branches.** As recorded against `2aa1702a`, this fork
develops on `main`; the pattern the new condition matches has nothing to match.
