# port — nuxt/ui@56b1156a9abaeb587221ac018d6c335c58a353be

**Upstream:** fix(Form): keep dirty state and validation in sync with input (#7033)

**Decision:** port.

Several races between input events, their debounced validation and a submit:

- `useFormField` debounced the whole `input` event, so a submit inside
  `validateOnInputDelay` was followed by a late input that marked the field
  dirty again and re-validated it. The input is now emitted right away with
  `validate: false` (tracked: dirty/touched), and only the validation is
  debounced, emitted with `track: false`.
- `Form` keeps an `epoch`, bumped on every full validation. Field validations
  started before it, and input typed before it, are dropped as stale; a field
  validation superseded by a newer one for the same field (`validationRuns`) is
  dropped too, so an older run finishing last cannot overwrite newer errors.
- `clearDirty()` after submit keeps fields edited since the last full
  validation (during an async `onSubmit`) dirty instead of clearing them all.
- `validate({ name })` decides its result from the targeted fields only; errors
  on other fields are kept but no longer make it throw.
- `FormInputEvent` gains `track?` and `validate?` (public type, additive).

The fork's `Form.vue`, `useFormField.ts` and `types/form.ts` matched upstream's
pre-image apart from the §1 renames (`b24ui`, the `bitrix24-ui.*` injection
symbols, `air-primary-alert`, and the fork's `describedBy`), none of which the
hunks touch, so upstream's diff applied verbatim, specs included. No component
in the fork emits form-bus events except through `useFormField`, so nothing else
needed the new flags. Verified the new spec cases fail with the `src/` change
reverted.

**Deviations:** none.

`emitFormEvent`'s third parameter changed from `eager?: boolean` to a flags
object; it is internal to `useFormField` and not returned, so this is not a
public API change.
