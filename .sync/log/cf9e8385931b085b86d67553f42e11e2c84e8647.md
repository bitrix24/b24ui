**Upstream:** fix(SelectMenu): open menu on arrow keys (#6933)

**Decision:** port, verbatim, plus one test of our own. Third of three commits
in this run.

## The defect

reka gives the two halves of a combobox different keyboard behaviour:
`ComboboxInput` opens on ArrowDown/ArrowUp, `ComboboxTrigger` toggles on click
only. `SelectMenu` makes the **trigger** the focusable element — it carries
`tabindex="0"` — so the arrow keys did nothing, and a keyboard user could not
open the menu without pressing Enter or Space.

## Upstream fix

`onTriggerKeydown` bound to `@keydown.down` and `@keydown.up` on the trigger:
prevent the default and synthesise a click, which is what the trigger already
understands.

The `isOpen` early return is load-bearing rather than defensive. A click
**toggles**, so without it the arrow keys would close an open menu instead of
moving through its items — the fix would have swapped one keyboard bug for a
worse one.

## b24ui port

Applies verbatim. Our pre-image is upstream's at both sites: `onUpdateOpen` ends
the same way with `onCreate` following it, and the trigger carries `tabindex="0"`
followed by `v-bind="{ ...$attrs, ...ariaAttrs }"`. Only the template indentation
differs, this fork's trigger sitting one level deeper.

## Tests

Upstream's three cases, plus one of ours.

Mutation-checked, and the measurement changed what got written:

| mutation | upstream's cases | with ours added |
| --- | --- | --- |
| revert the port | **4 red** | 4 red |
| drop the `isOpen` guard | **2 red** | 2 red |
| remove `@keydown.up` only | **2 red** | 2 red |
| remove `e.preventDefault()` | **162 green** | **4 red** |

`preventDefault` is the reason an arrow key opens the menu instead of scrolling
the page, and nothing upstream wrote reaches it. One case added that dispatches a
real cancelable `KeyboardEvent` and asserts `defaultPrevented` — the assertion
has to be made on the event object, because `trigger('keydown')` hands back a
wrapper rather than the event.
