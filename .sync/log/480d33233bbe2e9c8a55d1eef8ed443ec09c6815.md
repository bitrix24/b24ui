# port — nuxt/ui@480d33233bbe2e9c8a55d1eef8ed443ec09c6815

**Upstream:** refactor(composables): use `unref` to simplify prop resolution (#6987)

**Decision:** port — both files match upstream's pre-image, and the rewrite is
an identity.

## The change

Two call sites stop hand-rolling what `unref` already is:

```ts
- const src = isRef(source) ? source.value : source     // useForwardProps.ts
+ const src = unref(source)

- ...(isRef(options) ? options.value : options)         // useResizable.ts
+ ...unref(options)
```

`unref(x)` is defined as `isRef(x) ? x.value : x`, so the two forms are the same
expression. Nothing can change.

`useForwardProps.ts` swaps `isRef` for `unref` in its import. `useResizable.ts`
keeps `isRef`, because it still uses it three more times — for the `collapsed`
option, not the `options` argument. Upstream's file ends in the same state.

## Coverage

No new test, and none is warranted for an identity. What is worth recording is
that **both branches are exercised by the existing suite**, so the rewrite is not
taken on trust that only one path runs:

- `useForwardProps` — 2 call sites pass a `computed(…)`, which is a ref; 37 pass
  `reactivePick(…)`, which is a reactive object and not a ref.
- `useResizable` — `DashboardPanel` and `DashboardSidebar` both pass
  `toRef(…)`, while `useResizable.spec.ts` passes plain objects.
