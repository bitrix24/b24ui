# port — nuxt/ui@12722057b3974acee4789f6a34aab05a18f6e835

**Upstream:** docs: fix raw markdown served to agents (#6914)

**Decision:** port, partial — the stringifier fix applies here; the
`nuxt-agent-discovery` half does not.

## Why a commit on skipped infrastructure was not a skip

The headline is about upstream's agent-discovery surface, which this fork
deliberately does not have: `9ef3ee39` built it and `ae243116` refactored it into
the `nuxt-agent-discovery` module, and both are recorded as skips. The reflex
answer here is a third skip, and it would have been wrong.

Reading the diff rather than the subject splits it in two. Half of it is the
module — bumping `nuxt-agent-discovery` `^0.1.1 → ^0.4.0`, deleting the
`prerenderRoutes()` calls that fed it, moving its `contentFilters` — and none of
that exists here. The other half fixes two defects in `minimark/stringify`,
**which this fork uses too**, through the same call:

```ts
stringify({ ...page.body, type: 'minimark' }, { format: 'markdown/html' })
```

in `docs/server/routes/raw/[...slug].md.get.ts`.

## The defects, measured rather than inferred

Run against our own installed `minimark`, on two nodes:

| node | what comes out |
| --- | --- |
| `table` | a literal `<table>` block — the format has no pipe-table handler |
| `pre` whose code holds ``` ``` `` | the `pre` handler always opens a three-backtick fence, so the inner pair **closes it early**: the remaining code becomes prose and a second block |

And they are not hypothetical here. `docs/content/` carries markdown tables in
**28** files and four-backtick fences in **7** — the typography pages that
document code blocks. All of it reaches `/raw/**.md`, which is what
`skills/b24-ui-nuxt/references/components.md` points agents at.

## The port

`docs/server/utils/markdown.ts` is taken as upstream wrote it: `pipeTable`
renders a `table` node as GFM with each cell reduced to inline markdown, and
`fencedBlock` opens a fence longer than any run inside the code. Both return a
string dropped into the tree as a paragraph, which the stringifier passes through
untouched. Only the module's own doc comment is adapted, because the sentence
about who absolutises links is not true here — see below.

Two passes are wired into `transformMDC.ts`, plus the small
`replaceNodeWithMarkdown` helper they share. Our `transformMDC.ts` is 1202 lines
against upstream's and diverges in its core — `castMap` rather than
`CAST_TEMPLATES`, our own `generateComponentCode`, `generateThemeConfig`,
`convertIcon`, `processLinks` — so upstream's hunks do not apply as a patch and
the passes were written against our file. Upstream's other additions in the same
commit (`KBD_LABELS`, `DROPPED_INLINE`, the `code-preview` template
reconstruction) belong to its own MDC vocabulary and were left alone.

### The ordering is load-bearing here and is not upstream

Upstream absolutises links **after** stringifying, inside
`nuxt-agent-discovery`, so its table pass can sit anywhere. Ours does it on the
tree: `processLinks` walks the nodes and rewrites `a.href` in place. `pipeTable`
flattens an `a` node into `[text](href)` **text**.

Render the tables first and the hrefs inside their cells are strings by the time
`processLinks` looks for nodes — left relative, pointing nowhere from a raw
markdown file served to an agent. So both passes run after `processLinks`, and
the call site says why.

Confirmed in the built output rather than argued: a generated cell reads
`[TanStack Virtual](https://tanstack.com/virtual/latest/docs/api/virtualizer)` —
rendered as a link, and absolute.

## Verification

`pnpm docs:generate`, then reading `docs/.output/public/raw`:

- **30** raw files now carry pipe tables; the one remaining `<table>` in the
  tree is prose — the Table page's note that the component *"supports all native
  `<table>` HTML attributes"* — not a rendered table.
- Fences longer than three backticks appear where the source needs them.
- Pipes inside code spans are escaped: `` `Ref<Virtualizer> \| undefined` ``,
  which without the escape would split one cell into two and shift the row.

## The `llms.txt` half, which turned up a gap of our own

Upstream also widens two `contentFilters` (`/docs/components/%` →
`/docs/components%`) and adds a Typography section. Both apply, and the first is
not the cosmetic tidy-up it looks like.

`LIKE '/docs/components/%'` matches everything *under* the section but not the
section's own page. Ours exists — `docs/content/docs/2.components/0.index.md`,
resolving to `/docs/components` — so the listing carried all 120 component pages
and not the page introducing them. Measured across a regenerate: **120 → 121**,
the new first entry being `[Components](…/raw/docs/components.md)`. Worth noting
the two filters above it were already written without the slash; the four
disagreeing was the oversight, not the fix.

The Typography section is a gap we had independently of upstream. Twenty pages
sit under `docs/content/docs/4.typography/`, and they matched **none** of our
four sections, so the prose components were absent from `llms.txt` entirely — the
only occurrence of the word in the whole file was inside another page's
description. After the change the section lists all **20**.

Not taken from this half: the `nuxt-agent-discovery` bump, the `prerenderRoutes()`
deletions that depend on the module serving those routes instead, and the
`minimumReleaseAgeExclude` entry for `nuxt-agent-discovery@0.4.0` — a
supply-chain exception for a package this fork does not install.

## Tests

`test/utils/raw-markdown.spec.ts`, twelve cases, and they run against the **real
`stringify`** rather than a description of it. Two of them assert the *premise* —
that minimark writes a table as HTML and breaks out of a self-fencing block — so
that if the dependency grows a table handler the workaround is reported as dead
weight instead of quietly staying wrong.

Five mutations verified, each failing its own assertion: fixing the fence at three
backticks (3 red), dropping the pipe escape in a code span, collapsing a link to
its text, not padding a short row, and dropping the header separator.

### The test needed a dependency this repository had not declared

Importing the real `stringify` turned out to need `minimark` at the root.
`docs/package.json` declares it; the root did not, and the root is what typechecks
`test/`. The gate caught it from two sides at once, which is worth recording
because each alone is easy to misread:

- `typecheck` — `TS2307: Cannot find module 'minimark/stringify'`;
- `test` — **one file failed with zero failed tests**, the shape of an import
  error rather than an assertion, in the `vue` project where the hoisted copy is
  not reachable either.

Fixed by declaring `minimark: ^0.2.0` in the root `devDependencies`, the same
range `docs` uses. The package was already in the tree, so the lockfile gains
three lines — the importer entry — and resolves no new package. Nothing to
reconcile in `dep-parity.json`: it compares only packages both trees declare in
the same section, and upstream declares `minimark` under `docs`, not at the root.
