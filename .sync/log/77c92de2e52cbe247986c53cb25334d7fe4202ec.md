# port — nuxt/ui@77c92de2e52cbe247986c53cb25334d7fe4202ec

**Upstream:** fix(module): generate classes prefixed by `usePrefix` (#7074)

**Decision:** port.

Components build some classes at runtime through `usePrefix()` (`prefix('hidden')`
and friends). With `theme.prefix` set, the prefix is only added at runtime, so
Tailwind's scan sees the bare class and never generates `tw:hidden`. Upstream
lists those classes in an exported `prefixedClasses` and, when a prefix is
configured, emits them as an `@source inline(...)` in the generated CSS.

The fork's components pass exactly the same twelve classes to `prefix()`, so the
list is carried verbatim. The new source sits in `generateSources()` outside the
`if (nuxt)` block, as upstream's does, so it reaches both adapters: Nuxt through
`src/module.ts` and Vue through `src/plugins/templates.ts`, which both call
`getTemplates()`.

**Deviations:** the spec cases. Our `test/utils/templates.spec.ts` is our own
(it guards `CSS_TEMPLATE_FILENAME`) and has no `themeContents` helper; the cases
read the CSS template through `isCssTemplate` instead of upstream's `ui.css`
filename, and a third case asserts nothing is emitted without `theme.prefix`.
Verified the prefix cases fail with the `src/templates.ts` change reverted.
