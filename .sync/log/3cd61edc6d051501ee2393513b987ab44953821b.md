# Port: fix(ProseA): hide underline on focus and around inline code

**Upstream:** `3cd61edc6d051501ee2393513b987ab44953821b` (nuxt/ui)
**Decision:** port — the focus half; the inline-code half and the Callout hunk have no defect to fix here

## Upstream change
Upstream draws a link's underline as a bottom border: `border-b
border-transparent hover:border-primary`. The commit changes two things:
- `src/theme/prose/a.ts` adds `focus-visible:border-transparent`, so a focused
  link shows only its focus outline and no underline, even under the pointer.
  It also adds `has-[>code]:border-b-0`. A link that wraps inline code already
  marks hover and focus on the `<code>` (dashed border, colour), and the
  anchor's own bottom border drew a second line under it.
- `src/theme/prose/callout.ts` adds `[&_a]:focus-visible:border-transparent` to
  each colour. Callout sets its own `[&_a]:hover:border-${color}`, and that
  descendant selector outranks ProseA's `focus-visible:` rule, so without the
  addition links inside a callout kept the underline on focus.

## b24ui port
The fork's `src/theme/prose/a.ts` is its own theme. It underlines with
`text-decoration` (`hover:underline underline-offset-2`), not a border, and
marks `[&>code]` with a ring and background. Same shape as the `3da141cb`
entry.

- **Focus:** `hover:underline` → `hover:not-focus-visible:underline`. Before
  the change, hovering a focused link drew the underline alongside the focus
  outline. Now the underline appears only while the link is hovered and not
  focus-visible, which is upstream's behaviour. Upstream overrides on focus;
  here the hover rule is gated instead. A sibling `focus-visible:no-underline`
  would have outranked Callout's permanent `[&_a]:underline` (`.x:focus-visible`
  0,2,0 against `.x a` 0,1,1), so every link in a callout would lose its
  underline on focus. That is a change upstream did not make, because
  upstream's callout links are not permanently underlined. Gating the hover
  rule leaves Callout alone.
- **Inline code:** nothing to change. Prose `code` here is `inline-block`
  (`src/theme/prose/code.ts`), and text decoration does not propagate into
  atomic inline boxes. So `hover:underline` on an `<a><code>…</code></a>` draws
  no line around the code. The double line upstream removes comes from its
  border-based underline, which the fork does not use.
- **`prose/callout.ts`:** no hunk. The fork's callout sets
  `[&_a]:underline` permanently, with no hover rule that would override the
  focus rule. Callout links stay underlined on focus, as they do at rest.
