# Port: fix(theme): blank top-level `base` in `applyUnstyled`

**Upstream:** `3e89ea791b9f91ea0e1e8abdf85e118452854921` (nuxt/ui, #6825)
**Decision:** port — verbatim (two bugs, both present here)

## Upstream change
`applyUnstyled` strips theme classes when `theme.unstyled` is enabled. It
handled `slots`, `variants` and `compoundVariants` — and missed two things:

```diff
+  // Copy before reassigning: object-shaped themes are the shared module export
+  // (function-shaped ones produce a fresh object per call), and blanking the
+  // shared object in place would blank every later read — the Vue dev server
+  // re-generates themes as component detection grows.
+  result = { ...result }
+
+  // Single-element components have no `slots`: their classes live in a
+  // top-level `base` string (or array, when parts are conditional).
+  if (result.base) {
+    result.base = ''
+  }
+
   if (result.slots) {
```

**Bug 1 — single-element components were never unstyled.** A component with no
`slots` keeps its classes in a top-level `base`. `applyUnstyled` never looked
there, so `unstyled: true` left those components fully styled.

**Bug 2 — the shared theme object was mutated in place.** For object-shaped
themes, what arrives is the module export itself; blanking its keys poisons
every later read in the same process.

Before this fix, `theme.unstyled: true` silently left all of them styled.

### Bug 2 is not theoretical here either
`src/templates.ts` does `const template = (theme as any)[component]` and then
`result = applyDefaultVariants(...)` → `result = applyUnstyled(...)`. For
object-shaped themes that is the shared export, and `applyDefaultVariants`
**also** returns its input unchanged by identity — it mutates in place and does
not copy — so `applyUnstyled` received the module export directly. `getContents`
is re-invoked as component detection grows (the surrounding
`previousDetectedComponents` bookkeeping exists for exactly that), so a blanked
theme would have leaked into subsequent generations.

Worth noting and *not* fixing here: `applyDefaultVariants` mutates in place too,
but its guards (`=== 'air-primary'`, `=== 'md'`) make a second application a
no-op, so it is idempotent rather than destructive. Out of this commit's scope.
