# Port: feat(Toast): add `closeOnClick` to actions (#7147)

**Upstream:** `378873a28d5db444c52873b21a71551609f11aa0` (nuxt/ui)
**Decision:** port

## Upstream change
Every Toast action closed the toast when clicked, because reka-ui's `ToastAction`
defaults `closeOnClick` to `true` and nothing could set it. Now an action can opt out:
- `ToastProps['actions']` becomes `(ButtonProps & { closeOnClick?: boolean })[]`,
  with jsDoc and `@defaultValue true`.
- Both `ToastAction` loops, vertical and horizontal, destructure
  `{ closeOnClick, ...action }`. `closeOnClick` goes to `ToastAction` as
  `:close-on-click`, and only the rest is bound to the button, so `closeonclick` never
  lands on the DOM. When it is `undefined`, Vue uses reka's `true` default.
- `Toast.spec.ts`: one `it.each` over both orientations. An action with
  `closeOnClick: false` emits no `update:open`, and a plain action still emits
  `[[false]]`.

No docs or playground change upstream.

## b24ui port
- `src/runtime/components/Toast.vue`: the same type and template changes. The fork's
  two loops differ from upstream's only in the button (`B24Button size="sm"
  :color="props.color as ButtonProps['color']"`), which is kept as it is. The jsDoc
  example stays `{ size: 'sm' }`, the fork's own size. `useToast`'s `Toast` extends
  `ToastProps`, so `toast.add({ actions: [{ …, closeOnClick: false }] })` is typed
  through the same change.
- reka-ui 2.11.0, already here, has `ToastActionProps.closeOnClick` (default `true`).
- No docs or playground change, as upstream.

## Tests
`test/components/Toast.spec.ts`: upstream's case, verbatim, before the a11y test. The
fork's `ToastWrapper` is the `B24*` equivalent. The fork's horizontal `actions` div
renders when `props.close !== null`, not when `props.close` is truthy, so with the
default `close` it also holds the close button. That button comes after the two
actions in DOM order, so the `[keep, close]` destructuring still picks the two actions.
No snapshots change: the "with actions" entries render the same markup, because
`closeOnClick` is taken off before `v-bind`.
