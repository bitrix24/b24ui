# Port: docs(mcp): clarify tool and resource descriptions

**Upstream:** `6c683b3ad4cecc3a9a3edbc9f32155a43b1729df` (nuxt/ui)
**Decision:** port (partial)

## Upstream change
Rewrites the description strings of the docs MCP server
(`docs/server/mcp/{tools,resources}/*.ts`) so each one says exactly what the
handler accepts and returns: accepted component-name spellings, the exact
`search-components` category list (and fixes the `category: 'forms'`
inputExample to `'form'`), the matching/sorting of `search-composables`, the
shape of `get-documentation-page` / `get-migration-guide` / `list-templates`
results, the single-collection behaviour of `search-icons`, and that the
composables/examples resources return names and short records only. No
handler logic changes.

## b24ui port
Each claim was checked against the fork's own handler before porting
(`Nuxt UI` → `Bitrix24 UI`, tool names → `b24-ui-*`, `UButton`/`u-button` →
`B24Button`/`b24-button`).

- `tools/b24-ui-get-component.ts`, `tools/b24-ui-get-component-metadata.ts` —
  **ported**. `normalizeComponentName` strips `B24` / `b24-`, the lookup
  kebab-cases the rest and `fetchComponentMetadata` camel/upper-cases it, so
  `Button`, `B24Button`, `button` and `b24-button` all resolve.
- `tools/b24-ui-search-components.ts` — **adapted**. Category list derived from
  `category:` frontmatter in `docs/content/docs/2.components/*.md`: upstream's
  thirteen plus `deprecated` (`sidebar-layout.md`), which the handler's
  `/docs/components/%` query also returns, so it is listed. The `'forms'`
  inputExample was already `'form'` here (fixed earlier); no change.
- `tools/b24-ui-search-composables.ts` — **ported**. Handler is identical to
  upstream: case-insensitive substring on name/title/description, all when no
  `search`, sorted by name, returns name/title/description/path/url. `useToast`
  and `useOverlay` exist in `3.composables/`. Its `path` (baseUrl + trailing
  slash) is accepted by `b24-ui-get-documentation-page`, which strips both.
- `tools/b24-ui-list-templates.ts` — **ported**. Handler identical (exact
  case-insensitive `framework` match, `{ templates, total }`);
  `b24-ui-get-template` exists.
- `tools/b24-ui-get-migration-guide.ts` — **adapted**. The page exists
  (`1.getting-started/3.migration.md`, v1 → v2) at
  `/docs/getting-started/migration` and the handler returns title, description,
  path, documentation and url. Dropped upstream's "The page is large." — the
  fork's guide is ~3.6 KB.
- `tools/b24-ui-get-documentation-page.ts` — **adapted**. The fork does not use
  `getAgentDocument`; it `$fetch`es its own `/raw/[...slug].md` route, which
  (a) prefixes YAML frontmatter (title, description, canonical URL), so "no
  metadata" became "headed by a short frontmatter"; (b) answers a missing path
  with a 200 "Page Not Found" Markdown stub, so the handler's `catch` never
  fires for it and "Fails when no page exists" is false — the description says
  so instead; (c) has no section → first-page redirect (a section path returns
  its `index` page where one exists — getting-started, components, typography —
  and the Not Found stub otherwise, e.g. composables), so that sentence is
  dropped. The `search-documentation` / `get-component` cross-references hold.
- `tools/b24-ui-search-icons.ts` — **n/a, unchanged**. The fork's handler is a
  stub returning `{ icons: [], total: 0 }` (`@todo make search from b24Icons`);
  upstream's text (one Iconify collection per call, `lucide` default, `preview`
  SVG URL) describes behaviour the fork does not have. The fork's existing
  description is already inaccurate in the same way; correcting it belongs
  with implementing the tool, not with this port.
- `resources/b24-ui-composables.ts` — **ported** (returns `path`, `title`,
  `description`; also drops the old "categorie" typo).
- `resources/b24-ui-examples.ts` — **ported** (`listComponentExamples()`
  returns the name list only).
