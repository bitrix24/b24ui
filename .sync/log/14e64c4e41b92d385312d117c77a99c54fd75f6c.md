# port — nuxt/ui@14e64c4e41b92d385312d117c77a99c54fd75f6c

**Upstream:** chore(skills): fix stale component APIs

**Decision:** port — five of six hunks. Upstream's `skills/nuxt-ui/` is this
fork's `skills/b24-ui-nuxt/`, and every hunk has a counterpart line there. Each
correction was checked against this fork's component rather than taken from
upstream's wording, since a skill that is wrong here teaches agents to write
broken code.

| file | hunk | here |
| --- | --- | --- |
| `components.md` | `B24Theme` is "scoped color overrides" | **ported.** `Theme.vue` takes `props?: ThemeDefaults` (prop defaults) and `b24ui?: ThemeUI` (class overrides); it has nothing to do with colour. |
| `guidelines/design-system.md` | `<B24Theme :b24ui="{ button: { slots: { base } } }">` | **already right.** The fork's example reads `{ button: { base: 'rounded-full' } }`. |
| `guidelines/design-system.md` | `componentDetection: ['Modal', 'Dropdown', …]` | **ported.** There is no `Dropdown.vue` in `src/runtime/components/` — only `DropdownMenu.vue`. |
| `layouts/dashboard.md` | `DashboardSidebarCollapse` "toggles sidebar on mobile" | **ported.** Its theme is `base: 'hidden lg:flex'`, so it is not even rendered on mobile. `DashboardNavbar` has `toggle?: boolean \| ButtonProps` defaulting to `true`, which is the mobile toggle. |
| `recipes/data-tables.md` | `<B24Pagination v-model="page">` | **ported.** `Pagination` exposes `page`, not `modelValue`, and reka's `PaginationRoot` emits `update:page` (`dist/Pagination/PaginationRoot.js:54`). A bare `v-model` binds a prop that does not exist. The fork's own `pagination.md` already says `v-model:page`. |
| `recipes/overlays.md` | `<B24CommandPalette v-model:open>` | **ported.** `CommandPalette` has no `open` prop at all — it has `close` and emits `update:open`. The fork's docs example `CommandPaletteOpenExample.vue` already wraps it in `<B24Modal v-model:open>` with `close` and `@update:open`, which is exactly upstream's new shape. |
