## Upstream change

One version — `reka-ui: 2.10.3 → 2.10.4`, an exact pin on both sides — and 1316
snapshot lines across RadioGroup, Select and Stepper. Every wrapper in this
library is a reka primitive, so a patch release there is a render change here.

## What reka 2.10.4 actually changes

Derived from upstream's own snapshot diff rather than from its release notes, by
matching each `-`/`+` pair and extracting the differing substring. Three changes,
nothing else:

| component | change |
| --- | --- |
| RadioGroup | `aria-label="<value>"` removed from the radio `button` |
| Stepper | the indicator `<div>` inside the trigger becomes a `<span>` |
| Select | `aria-controls="reka-select-content-…"` removed from the trigger |

## Why accepting the RadioGroup change is right, not merely upstream's choice

This one deserved a look before being accepted, because an `aria-label`
disappearing from a control reads like an accessibility regression. It is the
opposite.

Each radio here sits **inside** its `<label data-slot="item">`, which also holds
the visible `<span data-slot="label">Option 1</span>`. That is an implicit label
association, and it gives the button an accessible name on its own. While
`aria-label` was present it *won* over that association — and what it carried was
the item's **value**, not its label. So a radio whose visible text read "Option 1"
announced itself as "1".

Removing it hands the name back to the visible text. Strictly better, and the
reason the snapshot movement is a correction rather than a loss.

The Stepper change is HTML content-model hygiene — a `<div>` is not permitted
inside a `<button>` — and the Select one drops an `aria-controls` pointing at
content that does not exist until the listbox opens.

## b24ui port

The version bump is one line. The snapshots were regenerated with
`pnpm run test:update` and then **checked rather than trusted**, because `-u`
rewrites a real regression as readily as an expected change. The same extraction
run against our own diff gives the same three deltas and nothing else:

- **RadioGroup** (both projects, 102 lines each): only ` aria-label="…"`
  deletions.
- **Stepper** (both projects, 347 lines each): all **81** `<div
  data-slot="indicator">` became `<span>`; the rest of the churn is the
  pretty-printer rejoining lines around the shorter tag. Ours moves more lines
  than upstream's because our indicators hold inline `<svg>` from
  `@bitrix24/b24icons-vue` where upstream renders an iconify `<span>` (§1).
- **Select** (both projects, 10 lines each): 10 `aria-controls` removed, 35 left
  on other elements.

One further check, because a per-line diff can miss a deletion that lands
everywhere at once: the set of attribute **names** appearing in each of the three
snapshot files is identical before and after — nothing vanished from the markup
and nothing new appeared. Only the occurrences above changed.
