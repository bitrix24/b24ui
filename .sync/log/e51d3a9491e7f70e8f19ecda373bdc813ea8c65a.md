# port — nuxt/ui@e51d3a9491e7f70e8f19ecda373bdc813ea8c65a

**Upstream:** fix(useToast): skip pulse while toast is animating (#7195)

**Decision:** port (adapted).

## Problem
Re-adding a toast by `id` bumps `_duplicate`, which flips `data-pulsing`
between `odd`/`even` to replay the pulse. A bump during the slide-in replaced
it with a pulse, and two bumps in one tick cancelled each other out.

## Change
- **src/runtime/composables/useToast.ts** — internal `_animatedAt` on `Toast`
  (set when the toast is displayed and on each counted pulse); `mergeDuplicate`
  leaves `_duplicate` / `_animatedAt` unchanged while
  `Date.now() - _animatedAt < ANIMATION_DURATION`.
- **src/runtime/components/Toaster.vue** — `_animatedAt` added to the `omit()`
  list so it is not bound onto `B24Toast`.
- **test/composables/useToast.spec.ts** — upstream's fake-`Date` setup, the two
  new cases and the `toBeUndefined()` expectation changes.

## Adaptation
- `ANIMATION_DURATION` is **300**, not upstream's 200: b24ui's `toaster` theme
  runs the pulse at `300ms` (slide-in is `200ms`; upstream has both at 200).
  The window covers the longer of the two. Tests advance the clock by 300
  accordingly. Comment rewritten as JSDoc naming both durations.
