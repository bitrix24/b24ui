# Port: chore(deps): update tiptap to ^3.29.2

**Upstream:** `8d0b5a80c6518d4a87bd42df3e20d26cbe37d3f3` (nuxt/ui, #6819)
**Decision:** port — §2 manifest mirroring (full overlap)

## Upstream change
Manifest-only: every `@tiptap/*` range moves `^3.29.0` → `^3.29.2` — 17 entries
in the root `package.json`, plus `extension-emoji` / `extension-text-align` in
`docs`, `playgrounds/nuxt` and `playgrounds/vue`. Lockfile regenerated.

## b24ui port (§2)
Complete overlap: b24ui carries all 17 root ranges at `^3.29.0` and the same two
extensions in `docs`, `playgrounds/nuxt`, `playgrounds/vue` and the fork-only
`playgrounds/demo`. All moved to `^3.29.2`.

One extra site upstream does not have: **`pnpm-workspace.yaml`'s
`'@tiptap/pm': ^3.29.0` override**, a fork-only pin that exists to keep
ProseMirror a singleton. Left at `^3.29.0` it would have contradicted the
manifests, so it moves too. Worth noting that the install showed
`@tiptap/pm 3.29.1 → 3.29.2`: the override was already a patch ahead of the
declared `^3.29.0` everywhere else, so this also closes that drift.

## What is actually in 3.29.1 / 3.29.2
Checked the upstream releases rather than assuming:

- **3.29.1** — `@tiptap/react`: caret placement after splitting a block
  rendered with a React NodeView.
- **3.29.2** — `@tiptap/react`: caret jumping back to the previous block on
  Enter inside a React node view; `@tiptap/extension-find-and-replace`: only
  the active result keeps the current-result highlight.

Neither reaches b24ui. `@tiptap/react` is not installed (the fork is on
`@tiptap/vue-3`) and `extension-find-and-replace` is not used. So this is
version alignment, not a behaviour fix — which is the point: tiptap wants one
`@tiptap/core` and one `@tiptap/pm` across the whole extension set, and letting
17 ranges drift apart is how that breaks.

## Duplicate 3.29.0 tree left in place (deliberate)
After the bump the lockfile carries both `3.29.0` and `3.29.2` for most
`@tiptap/*` packages. Traced it: the `3.29.0` set hangs off
`nuxtseo-layer-devtools@5.3.0` → the **published `@nuxt/ui@4.8.2`**, which
declares its own `@tiptap/* ^3.29.0`. pnpm keeps those resolutions because
`^3.29.0` still satisfies them. Before this commit b24ui's own tiptap was also
3.29.0 and deduped against that tree; now it does not.

Left as-is on purpose:

- `@tiptap/pm` stays a **single** copy at 3.29.2 (the fork override), and every
  `prosemirror-*` package is single-copy too — the duplication is `@tiptap/core`
  and the extensions, not the editor state layer;
- the whole `3.29.0` set sits under a **dev-only devtools layer** in `docs`. It
  is not in b24ui's published dependency graph and does not reach consumers.

`pnpm dedupe` does collapse it — but it removes 210 packages and floats
unrelated ranges (`@nuxt/content` 3.14.0→3.15.2 in the demo playground, `joi`,
`valibot`, `vue-router`), rewriting ~2850 lockfile lines. Most of that bloat
predates this commit. Folding a tree-wide dedupe into a tiptap patch bump would
make the change unreviewable; it belongs in its own PR with its own
justification.
