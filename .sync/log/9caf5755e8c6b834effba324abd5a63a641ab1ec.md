# port — nuxt/ui@9caf5755e8c6b834effba324abd5a63a641ab1ec

**Upstream:** chore: lint tailwind classes in docs and playgrounds

**Decision:** port — the rule is infrastructure that transfers wholesale, and
pointing it at this fork's own entry points immediately found eight dead classes
the compiled stylesheet had been silently dropping.

## Upstream change

Adds `eslint-plugin-better-tailwindcss@^4.7.0` as a devDependency and a
`betterTailwindcssConfig(files, entryPoint, ignore)` helper that attaches the
plugin's `correctness-error` preset to the apps in the repo. Each app gets its
own Tailwind entry point, because that is what tells the plugin which utilities
actually exist. `src/theme` is deliberately left out — the plugin cannot read
`export default (options) => ({...})` until schoero/eslint-plugin-better-tailwindcss#397
ships.

Upstream then fixed what the new rule reported in four docs files: `text-md`
(not a utility — `text-base` is), `text-neutral`, and two `:ui` values that
concatenated strings in a way the plugin could not read.

## What changed here

The helper is upstream's, with three fork adaptations:

1. **`b24ui`, not `ui`.** The attribute regex became
   `['^(v-bind:|:)?b24ui$', [{ match: 'objectValues' }]]`. This is load-bearing,
   not cosmetic — see the mutation below.
2. **A fourth app.** `playgrounds/demo` is ours alone; it gets its own config
   against `playgrounds/demo/app/assets/css/main.css`.
3. **A shared `AIR_HOOK_CLASSES` ignore list.** Upstream passes `ignore` only to
   the docs config. Here the air design system is driven by real CSS selectors
   (`light`, `dark`, `base-mode`, `edge-light`, `edge-dark`, `style-filled`,
   `style-filled-boost`, `air-custom-bg`, `scrollbar-transparent`) shipped by
   `src/runtime/index.css` and `src/runtime/air-design-tokens/*.css`. They are
   not Tailwind utilities, so no entry point can generate them, and every app
   uses them. The docs list adds its own page-local hooks on top.

## What the rule found

87 reports. 72 are the ignore-list cases above; the remaining 15 reports cover
eight distinct classes, all real:

| Site | Class | Fix |
| --- | --- | --- |
| `playgrounds/{nuxt,demo}/app/pages/components/tooltip.vue:66` | `lex` | → `flex` |
| `docs/app/components/header/HeaderBottom.vue:24` | `ps-2px` | → `ps-[2px]` |
| `docs/app/components/content/{ComponentProps,ComponentPropsDeprecated,ComponentSlots}.vue` | `text-toned` | → `text-muted` |
| `docs/app/components/content/examples/listbox/ListboxTransferListExample.vue:38` | `text-highlighted` | removed |
| `playgrounds/nuxt/app/pages/chat.vue:159` | `hover:text-default` | removed |
| `playgrounds/{nuxt,demo}/app/components/ExampleCardSubTitle.vue:10` | `mb` | removed |
| `docs/app/components/content/ComponentExample.vue:251` | `[mask-image:…(0.18))` | removed |
| `playgrounds/{nuxt,demo}/app/pages/components/description-list.vue:218` | `ring` before `ring-0` | removed |

Two deserve their reasons written down.

**`lex` was a broken layout, not a dead class.** The element reads
`class="mb-4 lex flex-col gap-4"` — `flex-col` and `gap-4` with no `flex`, so the
tooltip demo column has been laying out as a block since it was written.

**The mask-image was one character from being much worse.** The class is
`[mask-image:linear-gradient(0deg,rgba(255,255,255,0.09),rgba(255,255,255,0.18))`
— no closing `]`, so Tailwind never compiled it. "Fixing" it by adding the
bracket would apply a 9%–18% alpha mask to every rendered component example in
the docs, i.e. make them nearly invisible. The class has never done anything and
was never meant to survive; it is removed, which is what the page renders today.
Upstream has no such class in `ComponentExample.vue` — it is fork-local debris.

`text-toned`, `text-highlighted` and `text-default` are nuxt/ui semantic colour
names. This fork defines `--text-color-{dimmed,muted,description,legend,label,
primary,primary-copilot}` in `src/runtime/index.css:46-54` and nothing else, so
all three have always resolved to nothing. `text-toned` marked prop/slot
description text, and `text-muted` is this fork's name for exactly that, so it is
a substitution; the other two carried no meaning the surrounding classes
(`font-medium`, `hover:bg-elevated/50`) do not already carry, so they are removed.

## Evidence

**Against built output, not source.** The docs' compiled stylesheet
(`docs/node_modules/.cache/nuxt/.nuxt/dist/client/_nuxt/entry.*.css`, built
before this change) contains `.text-muted{` once and contains no rule at all for
`text-toned`, `text-highlighted`, `ps-2px`, `lex` or `mb`. Every class removed
here was genuinely absent from the shipped CSS, so the six no-op removals are
provably no-ops and the two substitutions are the only rendering changes.

**Mutation — the rule is live in all four scopes.** Injecting
`zz-not-a-utility` into a `class` attribute raised
`better-tailwindcss/no-unknown-classes` in `docs/app`, `playgrounds/nuxt/app`,
`playgrounds/demo/app` and `playgrounds/vue/src`. The last one matters: that
playground reported zero real violations, so without the mutation there would be
no evidence its config was attached at all rather than silently skipped.

**Mutation — the `b24ui` rename is load-bearing.** Injecting the same class into
`actions: 'gap-0.5'` inside `:b24ui="{…}"` in `docs/app/components/chat/Chat.vue:220`
is reported with the attribute regex as written, and is **not** reported when
`^(v-bind:|:)?b24ui$` is changed to a name that matches nothing. Carrying
upstream's `ui` over unchanged would have left every `:b24ui` object in the repo
unlinted while the config still looked correct.

## Not covered

`src/theme` — same reason as upstream, and the same blocker: the plugin skips
`export default (options) => ({...})`. Note that this fork's theme files are
`export default {` (`src/theme/button.ts:19`), so the sibling commit `36d55434`
(the `.vscode` classRegex) does apply here even though this one does not.
