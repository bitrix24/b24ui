## Adaptation — locale matching
Upstream matches i18n tags against **file names** (`pt_br`, `fa_ir`, …).
b24ui's locale keys are its own short codes (`br`, `in`, `kz`, `la`, `sc`, `tc`,
`ua`, `vn`) and are not language tags — `in` is legacy Indonesian, `la` is
Latin, `sc` Sardinian — so matching by key would be wrong. Instead
`getLocaleTags()` reads each locale file's declared `locale:` tag (`pt-BR`,
`hi_IN`, `kk`, `es`, `zh-CN`, `zh-TW`, `uk`, `vi`) and `resolveLocaleKey()`
matches against that: exact tag, base language, then a base language with a
single regional locale (`pt` → `br`, `hi` → `in`; `zh` stays unmatched).
Upstream's `getLocaleKeys(): string[]` is therefore `getLocaleTags(): Record`.
