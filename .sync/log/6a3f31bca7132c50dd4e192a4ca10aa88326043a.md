## Why it does not apply

**The file is not here.** A grep for `renovate` across the tree, excluding
`node_modules`, `.git` and `.nuxt`, matches only `.sync/log/*.md` — earlier
journals describing upstream's renovate commits. Nothing in the repository is
configured by, or refers to, renovate.

**And the policy it configures is not ours.** Dependencies here are handled by
`.github/dependabot.yml`, whose own comments record the reasoning: github-actions
only, monthly, grouped into a single PR, with **npm deliberately excluded**
because this repository tracks nuxt/ui and takes dependency bumps as ports of
upstream's own through `.sync/`. A renovate config would either duplicate that
pipeline or compete with it.

So there is no line here to update, and nothing that would want updating in the
same direction: every removed key is about scheduling, lockfile maintenance and
dedupe for a bot this fork does not run.

## Worth noting for the sync rather than for this file

should be revisited — if `cursor` in `.sync/nuxt-ui.json` stops advancing for a
month while `nuxt/ui@v4` moves. This commit changes nothing about that, and the
cursor is current as of this run.

Same shape as `2aa1702a` (#596) and `a581357a` (#616): an upstream repository-
process file with no counterpart here.
