# No-op: docs(installation): add note about aliases in `theme.colors` option

**Upstream:** `6c1a66b955b28d7b40d6625734afddf3d2abb750` (nuxt/ui)
**Decision:** no-op — the option being documented does not exist here

## Upstream change
A `::note` added to both installation pages, warning that every alias listed in
the `theme.colors` module option generates a full set of `--ui-color-*` shades
and variants whether the app uses them or not, and that `error` must be kept if
forms are used because validation styling depends on it.

## Why it does not apply
The note documents the **`theme.colors` alias option**, which b24ui does not
have. The fork replaced upstream's semantic-alias colour system with Bitrix24's
`air-*` system, so there is no list of aliases to trim and no `--ui-color-*`
generation to warn about. Grep confirms it: `theme.colors` and a `colors: [` array
appear nowhere in either installation page.

Nothing to port — and writing an equivalent warning would mean inventing
guidance for machinery the fork does not ship.
