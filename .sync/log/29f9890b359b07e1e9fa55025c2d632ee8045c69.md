# Port: fix(Calendar): correct size scale

**Upstream:** `29f9890b359b07e1e9fa55025c2d632ee8045c69` (nuxt/ui, #6832)
**Decision:** port — two of three parts apply; the third was already done here

## Upstream change

Three fixes to `src/theme/calendar.ts`, plus the snapshot churn:

```diff
 const daySizes = {
-  xs: 'size-7',
+  xs: 'size-6',
   sm: 'size-7',
   md: 'size-8',
-  lg: 'size-9 text-md',
-  xl: 'size-10 text-lg'
+  lg: 'size-9',
+  xl: 'size-10'
 }
```

1. **`xs` was `sm`.** Both were `size-7`/`h-7`, so `size="xs"` rendered exactly
   `sm` — a prop accepted, documented and inert.
2. **`lg`/`xl` carried their own `text-…` on the cell trigger**, duplicating the
   font size the `size` variant sets on `cell`.
3. **`lg`/`xl` size variants gained `cell` and `cellWeek` text sizes**, and
   `lg`'s `text-md` became `text-base`, so the removal in (2) has something to
   fall back to.

## b24ui port

**Parts 1 and 2 apply and are ported.** Our maps carried the same duplicate step
(`xs`/`sm` both `size-7`/`h-7`) and the same stray text classes on `lg`
(`text-(length:--ui-font-size-lg)` on the day trigger, `text-md` on the picker).

`size-6`/`h-6` is not upstream's number taken on faith — it is 24px, which is
exactly what this fork's own scale uses for `xs` elsewhere (`src/theme/input.ts`:
`xs: h-[24px]`, `sm: h-[28px]` = `h-7`). The step lands where the rest of the
library puts it.

**Part 3 is already done here.** All four of our size variants set both `cell`
and `cellWeek`; upstream was catching up to a shape this fork already had. The
`text-md` → `text-base` rename is upstream-only too: `--text-md` is a real token
here (14px, `air-design-tokens/tw-style/font-size.css`), where upstream has no
such utility.

There is no `xl` — this fork's Calendar scale is `xs`/`sm`/`md`/`lg`.

Worth naming the user-visible half: with `text-md` gone from `pickerSizes.lg`,
the month and year pickers at `size="lg"` stop rendering at 14px and pick up the
`lg` font size from `cell`, matching the day grid they switch between.

## Tests

Snapshots: 4 updated (`xs` and `lg`, both projects). Nothing else moved — the
picker map has no snapshot at all, because `Calendar.spec.ts` renders the day
view only.

`test/utils/calendar-size-scale.spec.ts` (new). Snapshots are the wrong
instrument for this defect: a duplicate step produces two *identical* snapshots
rather than a failure, and half the data is not rendered by any spec. The guard
reads both maps back out of `compoundVariants` and asserts what the maps are
supposed to be — every declared size covered, every step distinct, no `text-…`
on the trigger, and a `cell` font size for every size now that the trigger no
longer carries one.

Mutations tried, each red: put `xs: 'size-7'` back; put `text-md` back on the
`lg` picker; drop `xs` from the picker map; blank `size.lg`'s `cell`.
