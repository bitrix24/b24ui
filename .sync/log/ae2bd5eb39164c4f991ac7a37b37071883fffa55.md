# Port: feat(Splitter): new component

**Upstream:** `ae2bd5eb39164c4f991ac7a37b37071883fffa55` (nuxt/ui, #6670)
**Decision:** port — adopted by decision, adapted to b24ui

## Upstream change

A new `Splitter`: resizable panels separated by draggable handles, wrapping
reka-ui's `SplitterGroup` / `SplitterPanel` / `SplitterResizeHandle`. 19 files,
815 insertions — component, theme, types, tests, snapshots, docs page with four
examples, playground page, skills references, and two preview images.

## Decision

Adopting a whole new component is not a mechanical port, so it was put to the
maintainer with the alternatives (adopt / skip / defer to an issue). Answer:
adopt and adapt.

Worth recording that it does **not** duplicate anything here. We already have
`DashboardPanel` and `DashboardResizeHandle`, but those build on reka-ui's
`Primitive` rather than its splitter primitives — checked before proposing,
because "we already have something like that" would have been the cheap wrong
answer.

## Adaptation

Mechanical, per §1: `ui` → `b24ui` throughout (prop, slot props, item key,
`appConfig.b24ui?.splitter`), `#build/ui/splitter` → `#build/b24ui/splitter`.
The reka-ui imports keep their own names, so the template is upstream's.

Theme, adapted rather than copied. Upstream's handle focus ring is
`focus-visible:outline-2 focus-visible:outline-primary`; ours follows the
convention in `button.ts` and `checkbox.ts` —
`outline-transparent focus-visible:outline-2 focus-visible:outline-offset-2`
with a token, `--ui-color-accent-soft-element-blue`, the same one `table.ts`
uses for focusable rows.

Registered in the three places a component has to be: `src/theme/index.ts`,
`src/runtime/types/index.ts`, and `src/runtime/types/theme.ts`. The last one has
two blocks and the `prose` one closes at line 159 — the entry belongs in the
outer block, between `slideover` and `stepper`, which is where it went.

Docs, examples and the playground page were translated rather than copied:
upstream's `bg-elevated/50 border-default text-muted` become our
`bg-(--ui-color-bg-content-secondary)`, `border-(--ui-color-divider-default)`
and `text-description`; `color="neutral" variant="subtle"` becomes
`color="air-secondary"`, since b24ui's Button has no `variant`; and the
collapsible example's `i-lucide-panel-left-{open,close}` become the b24icons the
dictionary maps `panelOpen` / `panelClose` to — `outline/OpenChatIcon` and
`outline/CloseChatIcon`, not `main/…`, which is where a first guess put them.

**Not ported:** `docs/public/components/{light,dark}/splitter.png`. Those feed a
preview grid this fork does not have — `docs/public/components/` does not exist
here and nothing references it.

## Tests

Upstream's spec, with `ui` → `b24ui` and its `bg-primary` probe class replaced by
a token. 24 snapshots generated on our theme, plus the axe pass, all green.

The snapshots are worth one check rather than a glance: the rendered handle
carries our focus ring, so the theme adaptation is in the output rather than
only in the source.
