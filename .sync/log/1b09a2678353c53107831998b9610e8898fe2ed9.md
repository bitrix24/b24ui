# Port: perf(Toaster): lazy load toast component (#7163)

**Upstream:** `1b09a2678353c53107831998b9610e8898fe2ed9` (nuxt/ui)
**Decision:** port

## Upstream change
`Toaster.vue` only. The static `import UToast from './Toast.vue'` is replaced by
`defineAsyncComponent(() => import('./Toast.vue'))`, so the Toast chunk stays out of the
bundle of every page that mounts a Toaster (usually the root `App`). On mount, the
Toaster schedules the same loader with `requestIdleCallback` from `utils/prefetch`, so
the chunk is already there when the first toast fires. The comment notes a toast is
often shown right after the network failed. `onBeforeUnmount` cancels the idle callback.
No tests, docs or playground changes.

## b24ui port
`src/runtime/components/Toaster.vue`: the same change, verbatim except the local is
named `B24Toast` (the fork's template tag), not `UToast`.
- `utils/prefetch.ts` already exists in the fork with the same `requestIdleCallback` /
  `cancelIdleCallback` pair (SSR-safe, `setTimeout` fallback, `undefined` handle is a
  no-op on cancel). No change needed.
- Keeping the `B24Toast` name matters for `experimental.componentDetection`:
  `buildComponentDependencyGraph` (`src/utils/components.ts`) finds edges by matching
  `B24<Name>` text in each component file. The `<B24Toast>` template tag is still
  there, so Toaster -> Toast stays in the graph and Toast's CSS is still generated.

## Two build adapters
The dynamic import is a relative `import('./Toast.vue')` inside a runtime SFC. It
resolves the same way under `src/module.ts` (Nuxt/Vite) and `src/unplugin.ts`
(Vue/Vite). Neither adapter needs a change, and nothing resolves from `import.meta.url`.
This is a local module, not remote code, so the §5 rule on dynamic `import()` does not
apply.

## Tests
None from upstream. `test/components/Toast.spec.ts` snapshots mount `B24Toast`
directly inside the wrapper, not through the Toaster's async list. The `useToast`-driven
cases already wait with `vi.waitFor`. No snapshot changes are expected.
