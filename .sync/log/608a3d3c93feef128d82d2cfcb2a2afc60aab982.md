# Port: fix(Slideover): only cap width from `sm` breakpoint (#7156)

**Upstream:** `608a3d3c93feef128d82d2cfcb2a2afc60aab982` (nuxt/ui)
**Decision:** n/a

## Upstream change
In `src/theme/slideover.ts`, the `side: right` and `side: left` variants used to set
`content: 'max-w-md'`. Upstream changes both to `sm:max-w-md`. A side slideover now
fills the screen width on phones and is capped at `max-w-md` (28rem) only from `sm` up.
The rest of the diff is snapshots: Slideover, plus Header and DashboardSidebar, which
render a side slideover for their mobile menu.

## b24ui port
Nothing to port. The fork's `src/theme/slideover.ts` has its own widths, modelled on the
Bitrix24 SidePanel, and has no `max-w-*` cap at all:
- `side.right` / `side.left` set `content: ''` (plus a header height). There is no
  `max-w-md` to move behind `sm:`.
- Width comes from the `side` × `inset` compound variants. With `inset: false`, right
  and left use `w-[calc(100%-60px)] sm:w-[calc(100%-150px)]`, so they are already
  close to full width on small screens. `inset: true` uses `w-[calc(100%-2rem)]`.
- `src/theme/header.ts` and `src/theme/dashboard-sidebar.ts` add no `max-w-*` to the
  slideover either.

The behaviour upstream wants (no narrow cap on phones) is already what the fork does.
Same reasoning as `3da141cb` (ProseA), where the fork's theme had no `rounded-*` to make
conditional.
