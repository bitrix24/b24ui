## Open question
Upstream's title is "align link styles with prose", but **in this fork the
Editor's links and `B24ProseA` already differ structurally**:

| | fork `editor.ts` | fork `prose/a.ts` |
|---|---|---|
| underline | `border-b`, transparent until hover | `hover:underline underline-offset-2` (text-decoration) |
| colour | `--ui-color-accent-main-primary` | `--ui-color-accent-main-link` / `dark:--ui-color-blue-40` |
| focus ring | none set | `focus-visible:outline-info-text` (colour only; browser-default width) |
| code in link | dashed border, blue border on hover | ring + selection background on hover/focus |

The fork also has no single focus-ring convention to map `outline-primary/25
outline-3 rounded-xs` onto. `link.ts` uses
`outline-(--ui-color-design-outline-focused-stroke) outline-1 rounded-[4px]`,
`prose/a.ts` uses `outline-info-text`, and the heading anchors use
`outline-(--ui-color-accent-main-primary)`.

So which should Editor links align with?
1. **Upstream's styles, mechanically tokenised.** Keep the border underline
   and add the three items above plus a focus ring. Someone has to pick the
   ring's colour, width and radius from the options listed.
2. **The fork's own `B24ProseA`.** Switch Editor links to text-decoration
   underline and the link colour, and give code-in-link ProseA's ring and
   selection treatment. This is what "align with prose" means in this repo,
   and it is a visible restyle of the Editor.
3. **Only the unambiguous part** (no underline on focus, no underline around
   code), with no focus ring added. A partial port.
