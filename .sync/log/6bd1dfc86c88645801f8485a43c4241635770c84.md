# Port: perf(Button/Select/SelectMenu/InputMenu): narrow reactive dependencies

**Upstream:** `6bd1dfc86c88645801f8485a43c4241635770c84` (nuxt/ui)
**Decision:** port — adapted to b24ui's prop/composable surface

## Upstream change
Two independent perf fixes plus two new benchmarks:
1. **Button** — memoize `omit(linkProps, ['type','disabled','onClick'])` into a
   `forwardedLinkProps` computed instead of calling it inline in the template
   (the `omit` walks every forwarded key through three proxy layers on every
   render).
2. **Button / Select / SelectMenu / InputMenu** — stop feeding
   `useComponentIcons` a wide object (`{ ...props }` / `defu(props, …)`). That
   copies every prop through the `useComponentProps` proxy and subscribes the
   computed — and `ui`, which reads `isLeading`/`isTrailing` — to all of them,
   re-running the whole tv pipeline on unrelated changes like `class`. Now only
   the keys the composable actually reads are passed.
3. New `test/bench/button-link.bench.ts` and `test/bench/link-stack.bench.ts`.

## b24ui port
- **`Button.vue`** — narrowed `useComponentIcons` input from
  `{ ...props, loading: false }` to `{ icon, avatar, loading: false }`.
  b24ui's `UseComponentIconsProps` declares `icon` / `avatar` / `loading` /
  `trailing` / `trailingIcon`, and `ButtonProps` omits `trailing` /
  `trailingIcon`, so those two keys have no counterpart here. `loading: false`
  is b24ui's existing behaviour (its Button drives the loading icon through the
  `useWait` / `useClock` variants) and is preserved exactly.
- **`Select.vue` / `SelectMenu.vue` / `InputMenu.vue`** — replaced
  `toRef(() => defu(props, { trailingIcon: icons.chevronDown }))` with a
  computed passing `{ icon, avatar, trailing, trailingIcon, loading }`.
  `props.trailingIcon ?? icons.chevronDown` is exactly `defu`'s semantics for
  this key (source wins, `undefined` falls back to the default). All three
  extend `UseComponentIconsProps` and declare `avatar`, so the narrowed set is
  complete. b24ui reads the icon from its own `icons` dictionary rather than
  upstream's `appConfig.ui.icons`.
- **Benchmarks** — ported both files with b24ui naming (`B24Button`,
  `B24Link`, `B24LinkBase`) and b24ui's import paths; `Link.vue` lives at
  `src/runtime/vue/overrides/vue-router/Link.vue` and `LinkBase.vue` /
  `Button.vue` under `src/runtime/components/`, all of which exist. `Primitive`
  comes from `reka-ui` as upstream.

### Already present — nothing to port
The **`omit` memoization** (fix 1). b24ui already computes it as
`proxyLinkProps` (added earlier for its own reason — the `@memo` note about
`omit` not being exported in the Vue docs build), and the template already
binds the computed rather than calling `omit` inline.
