# port — nuxt/ui@22efd35d12336b507afaa5fc9498c90df4292ea0

**Upstream:** fix(PinInput): emit blur whenever focus leaves the group (#6858)

**Decision:** port, verbatim. Second of three commits in this run.

## The defect

Each pin carried `@blur="onBlur"`, and `onBlur` fired only when
`!event.relatedTarget`:

```ts
function onBlur(event: FocusEvent) {
  if (!event.relatedTarget) {
    emits('blur', event)
    emitFormBlur()
  }
}
```

`relatedTarget` is the element receiving focus, and it is set both when focus
moves to the *next pin* and when it moves to something *outside the group*. The
guard could not tell those apart, so it suppressed both. Moving between pins not
emitting is right — but by accident; tabbing out of the component to another
field emitted nothing, which is not.

**Measured on our own code rather than taken from upstream's description.**
Dispatching a real `blur` on the first pin with `relatedTarget: document.body` —
what the browser does when focus leaves for another element — against the
pre-image:

```
{ blurEmitted: 'НЕ ЭМИТИЛСЯ' }
```

Nothing. And `emitFormBlur` sits behind the same guard, so `validate-on="blur"`
never ran for a `PinInput` a user tabbed out of.

## Upstream fix

The listener moves from each pin to the root, and from `blur`/`focus` to
`focusout`/`focusin` — those bubble, so one handler covers the group. Each
handler returns early when `currentTarget.contains(relatedTarget)`, which is the
test the old guard could not express: *did focus stay inside this component?*

`focus` is **new**. The pins forwarded `emitFormFocus` but emitted no public
event, so a caller had nothing to listen to. The emit type gains
`focus: [event: Event]` — an addition to the public API, not a change to it.

## b24ui port

Applies verbatim. Our pre-image is upstream's line for line at all four sites;
only this fork's `b24ui` naming differs and it is not on a changed line.

## Tests

Upstream's two new cases, plus their two rewrites of existing ones — the old
cases drove `blur` through `trigger('blur')`, which no longer reaches anything
now that the listener is on the root, so they dispatch `focusout` instead. That
includes the form-integration case, where the point is that `validate-on="blur"`
still fires.

Mutation-checked, and each mutation lands on a different assertion:

| mutation | result |
| --- | --- |
| revert the port | **8 red** |
| drop the `contains` guard in `onFocusOut` | **2 red** — blur now fires between pins |
| drop it in `onFocusIn` | **2 red** — focus fires between pins |
| remove `@focusin` from the root | **2 red** — no `focus` event at all |

The first row is weaker evidence than it looks and is worth saying so: the
pre-image listens to a different event, so the new cases fail there because
nothing is listening, not because the guard logic is wrong. The three guard
mutations are what actually pin the behaviour, and the probe above is what pins
the defect.
