# port — nuxt/ui@6138bf09d8c9a4e7d971cb76a88fbe6b67619c8e

**Upstream:** fix(Select/SelectMenu): keep focus moved on selection (#7083)

**Decision:** port.

An `@update:model-value` handler that moves focus elsewhere (to the next field,
say) lost it: after the close animation the menu restored focus to its trigger.
Upstream:

- `Select` handles `SelectContent`'s `close-auto-focus` and prevents the
  restore when focus has already moved outside the content.
- `SelectMenu` does the same on its `FocusScope`'s `unmount-auto-focus`, and
  switches the scope from `trapped` to `loop`: a trapped scope pulled focus
  back while the menu was closing, so the move never landed. An enclosing
  Modal's trap is still paused by reka's focus-scope stack.
- the `select` theme's `content` gets `data-[state=closed]:pointer-events-none!`
  so a menu still mounted for its exit animation cannot swallow the click that
  moves focus. `SelectMenu`'s content extends `select`'s, so it gets it too.

The fork's two components matched upstream's pre-image at both sites apart from
the §1 `ui` → `b24ui` rename; the theme class was appended to the fork's own
`content` array. Snapshots: 170 updated, and the only change in them is that
class. Upstream's two `focus` spec cases added; both fail with the `src/`
change reverted.

**Deviations:** none.
