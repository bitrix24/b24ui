# Port: feat(ChatReasoning): add `autoOpen` prop

**Upstream:** `dad748e230314aed88fc555da93089185d49c1a3` (nuxt/ui, #7049)
**Decision:** port — verbatim apart from mechanical renames, plus a `Soon` badge

## Upstream change

`ChatReasoning` always opened itself when `streaming` became `true`. A new
`autoOpen` prop (default `true`, so behaviour is unchanged) gates that:

```diff
-const internalOpen = ref(props.defaultOpen ?? props.streaming)
+const internalOpen = ref(props.defaultOpen ?? (props.streaming && props.autoOpen))
...
     if (!wasStreaming) {
-      setOpen(true)
+      if (props.autoOpen) {
+        setOpen(true)
+      }
```

The prop gets JSDoc with `@defaultValue true` and an `autoOpen: true` entry in
`withDefaults`. The docs gain a tip pairing `auto-open="false"` with
`auto-close-delay="0"`.

## b24ui port

The fork's pre-image matched upstream's line for line except the usual
divergences (`IconComponent` icon types, `b24ui` instead of `ui`), so all four
hunks applied unchanged. `props` here is the `useComponentProps('chatReasoning', _props)`
proxy, so `props.autoOpen` also picks up a `<B24Theme :props>` default; the
initial `ref(...)` and the `immediate` watcher both read the proxy, as the
upstream lines read `props`.

Docs: the upstream tip is added above the `isPartStreaming` tip, unchanged.
Upstream adds no heading, so the fork's `Soon` badge goes on the existing
`### Streaming` heading, which is the section the new prop belongs to.

## Tests

Upstream's renderEach case `with streaming and autoOpen false` and its
`does not auto-open when streaming starts with autoOpen false` test, unchanged.
Snapshots regenerated with `-u` for both projects (`ChatReasoning.spec.ts.snap`
and `ChatReasoning-vue.spec.ts.snap`, one new entry each, `data-state="closed"`).

Mutation check: replacing the watcher's `if (props.autoOpen)` with `if (true)`
fails both new cases in both projects (4 failures). The snapshot case fails too,
because the `immediate` watcher calls `setOpen(true)` on mount.
