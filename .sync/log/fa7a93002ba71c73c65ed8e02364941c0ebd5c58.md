# Port: chore(deps): update reka-ui to v2.11.0 (#7127)

**Upstream:** `fa7a93002ba71c73c65ed8e02364941c0ebd5c58` (nuxt/ui)
**Decision:** port

## Upstream change
Upstream bumps the exact `reka-ui` pin from 2.10.5 to 2.11.0 in the catalog. The new reka-ui
depends on `@floating-ui/vue@2.0.1`, which drops `vue-demi`, and it no longer lists
`@floating-ui/dom` directly. Upstream then adapts to API changes in 2.11.0:
- `ContextMenu`: `ContextMenuRootProps` now has `open` and `pressOpenDelay`. Both are omitted
  from `ContextMenuProps`, as `dir` already was.
- `Toaster`: `ToastProviderProps` now has `limit` and `toastManager`. Both are omitted from
  `ToasterProps`. `ToastProvider` is the root element, so stray attributes would fall
  through as those props. `defineOptions({ inheritAttrs: false })` prevents that.
- reka-ui's `ToastRootImpl` now sets its own `data-expanded` (empty string while the
  provider is hovered or focused). That collides with the `data-expanded="true|false"` that
  Toaster put on each toast. The toast now gets `data-collapsed="!expanded"` instead, and
  the theme's `base` slot reads `data-[collapsed=true]` instead of `data-[expanded=false]`.
  `ToastViewport` also sets `data-expanded` now, but it merges `$attrs` last, so Toaster's
  explicit `data-expanded` still wins there. The `viewport` slot keeps
  `data-[expanded=true]`.
- `NavigationMenu`: on a horizontal item that has both a `to` and children, a click on the
  trailing area used to call `preventDefault()` in `onLinkTrailingClick`. reka-ui 2.11's
  trigger click handler ignores prevented events, so the submenu stopped opening. The
  handler now records the event in a `trailingClicks` WeakSet. The new `onLinkClick` is
  bound on the link, runs after the trigger's handler and before `LinkBase` calls
  `navigate`, and prevents the default there.
- Tests: there is a new NavigationMenu case for the trailing-area toggle. There are two
  new Toast cases: stacked toasts are marked collapsed, and attributes do not reach the
  provider. Toast's axe check now runs with no disabled rules.

## b24ui port
`.sync/PORTING.md` §2 says `reka-ui` is exact-pinned because upstream pins it, and that it
moves only through a port. This is that port.

- `pnpm-workspace.yaml`: the catalog entry `reka-ui: 2.10.5` is now `2.11.0`, an exact
  pin with no caret. The fork has no `overrides:` entry for reka-ui.
- `pnpm-lock.yaml`: the lockfile change is the same set upstream made. reka-ui moves from
  2.10.5 to 2.11.0, `@floating-ui/vue@2.0.1` is added, and the `vaul-vue` peer suffix
  follows. No other package version changes.
  - A plain `pnpm install --lockfile-only` also reshuffled the peer contexts of about 25
    unrelated snapshots: `oxc-parser` 0.139/0.140, `esbuild` 0.27/0.28 and the `nuxt`
    hashes. So the lockfile was edited by hand down to upstream's change instead.
  - `pnpm install --lockfile-only` leaves that hand-edited file byte-identical, and
    `pnpm install --frozen-lockfile --lockfile-only` passes.
  - `@floating-ui/vue@1.1.11`, `vue-demi` and `reka-ui@2.9.9` stay in the lockfile. They
    belong to the docs dependency `@nuxt/ui@4.8.2`, which pins its own reka-ui.
- `src/runtime/components/ContextMenu.vue`: adds `'open' | 'pressOpenDelay'` to the Omit,
  verbatim. `rootProps` picks only `modal`, so nothing else changes.
- `src/runtime/components/Toaster.vue`:
  - Adds `'limit' | 'toastManager'` to the Omit.
  - Adds `defineOptions({ inheritAttrs: false })` with upstream's comment after
    `defineSlots`.
  - Changes the `<B24Toast>` binding from `:data-expanded="expanded"` to
    `:data-collapsed="!expanded"`.
  - The second `:data-expanded` belongs to `<ToastViewport>`. Upstream leaves it as it is,
    and so does the fork.
  - The template never binds `$attrs`. `class` is a declared prop, already routed to the
    viewport, so `inheritAttrs: false` drops nothing the fork relied on.
- `src/theme/toaster.ts`: the 3 `data-[expanded=false]` tokens in `base` are now
  `data-[collapsed=true]`. Only those tokens changed. The fork's own differences in that
  string are kept: 300ms pulses and no `motion-safe:` prefix.
- `src/runtime/components/NavigationMenu.vue`: `trailingClicks` and `onLinkClick` are
  ported verbatim. The fork's template has five `B24LinkBase` elements. `@click="onLinkClick"`
  goes only on the counterparts of upstream's two:
  - the `B24LinkBase` inside `B24Tooltip`;
  - the `v-else` `B24LinkBase` inside the trigger `<component>`.

  It does not go on the `B24Popover` link or on the child links.
