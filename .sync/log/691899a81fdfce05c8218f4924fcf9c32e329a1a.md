# Port: perf(Header/DashboardSidebar/Sidebar): lazy load menu overlay (#7160)

**Upstream:** `691899a81fdfce05c8218f4924fcf9c32e329a1a` (nuxt/ui)
**Decision:** port

## Upstream change
The three components that open a mobile menu stop importing `Modal`, `Slideover`
and `Drawer` statically:
- `utils/lazy-overlay.ts` (new): `lazyOverlays` wraps the three components in
  `defineAsyncComponent` around relative dynamic `import()`s, and `loadOverlay(mode)`
  runs one loader.
- `composables/useLazyOverlay.ts` (new): returns a ref that is `false` until the
  `open` getter is first truthy, then stays `true`. After mount it preloads the
  overlay once the browser is idle (`requestIdleCallback` from `utils/prefetch`).
- `Header` / `DashboardSidebar`: `<Menu v-if="renderMenu">`. The menu also renders
  up front when `menu.unmountOnHide === false`.
- `Sidebar`: the same, keyed on `openMobile`, and it preloads only on mobile.
- Tests: snapshot callbacks await `vi.dynamicImportSettled()`. New "mounts the menu
  once opened" and "`unmountOnHide: false`" cases, a `useLazyOverlay` spec, and a
  `detectUsedComponents` case checking that the overlays stay in the dependency
  closure.

## b24ui port
- The two new files are copied verbatim. `utils/prefetch.ts` here exports the same
  `requestIdleCallback` / `cancelIdleCallback`.
- `Header.vue`, `DashboardSidebar.vue`, `Sidebar.vue`: the hunks are ported with the
  `U*` → `B24*` rename. The destructure keeps the `B24Slideover` / `B24Modal` /
  `B24Drawer` identifiers on purpose. `buildComponentDependencyGraph` in
  `src/utils/components.ts` matches `B24<Name>` identifiers, so the overlays stay in
  the detected closure and keep their theme CSS. `renderMenu` goes after the fork's
  longer `menuProps` block (the `@memo` b24ui overlay/content merge), which is
  otherwise untouched.
- Both build adapters: the loaders are plain relative `import()`s of `.vue` files
  inside `runtime/`, and `defineAsyncComponent` comes from `vue`. No Nuxt `Lazy*`
  prefix or auto-import is involved, so the Nuxt module and the Vue unplugin build
  resolve them the same way. Component detection is the shared `src/utils/components.ts`,
  used by both `src/templates.ts` and `src/plugins/templates.ts`.

- `Sidebar.spec.ts`: the new cases are ported by hand, since context drifted.
- `test/composables/useLazyOverlay.spec.ts`: verbatim.
- `test/utils/components.spec.ts`: the new case, with the `B24` prefix.
