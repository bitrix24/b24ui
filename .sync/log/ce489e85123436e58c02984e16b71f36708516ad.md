# Port: docs(mcp): resolve examples by their prerendered name

**Upstream:** `ce489e85123436e58c02984e16b71f36708516ad` (nuxt/ui, #6831)
**Decision:** port — and the class it belongs to, swept

## Upstream change

Three lines in `get-example.ts`. The tool passed `exampleName` straight into
`/api/component-example/${exampleName}.json`, but examples are prerendered under
their **camelCase** name, so a PascalCase argument — which is what the tool's own
`inputSchema` asks for — misses the prerendered file:

```diff
-      const result = await $fetch<{ code: string }>(`/api/component-example/${exampleName}.json`)
+      // Examples are prerendered under their camelCase name, the dynamic route accepts any case
+      const result = await $fetch<{ code: string }>(`/api/component-example/${camelCase(exampleName)}.json`)
```

It also replaced both `inputExamples` — `ButtonBasic` and `ModalOverlay` — with
names that exist: `TabsExample` and `AccordionBodySlotExample`.

## b24ui port

Applied verbatim; both replacement names exist here too
(`docs/app/components/content/examples/tabs/TabsExample.vue`,
`accordion/AccordionBodySlotExample.vue`), and the two originals are as fictional
here as they were upstream.

**This matters more here than upstream, and the comment says so.** Upstream's
note — "the dynamic route accepts any case" — is true of a server deployment.
This docs site is a **static** build (`docs:full:generate` → GitHub Pages), so
`docs/server/api/component-example.get.ts` is not running in production; the only
things that exist are the 377 prerendered `*.json` files, all camelCase. A
PascalCase name is a hard 404 with nothing to fall back to.

## The wider class

`inputExamples` is advertised to the client — an assistant reads it to learn what
a valid argument looks like and will call the tool with one verbatim. Every entry
is therefore a claim that something exists, and nothing anywhere checks it: the
values are only read at call time, and a 404 or an empty array looks like a
normal answer.

Auditing the other eleven tools the same way turned up two more false claims:

- `b24-ui-search-components` offered `{ category: 'forms', search: 'input' }`.
  The collection enum spells it `form`, so the example returns an empty list.
  Upstream has the same value. → `'form'`.
- `b24-ui-get-documentation-page` offered
  `path: '/b24ui/docs/getting-started/installation/'`, which is a **directory**
  here — the pages are `installation/nuxt` and `installation/vue`. The handler
  fetches `/raw/docs/getting-started/installation.md`, which is not generated.
  → `installation/nuxt/`.

## Tests

`test/utils/mcp-input-examples.spec.ts` (new) resolves every `inputExamples`
value that *can* be resolved against the tree: `exampleName` against the example
components, `componentName` against the component pages (prefix stripped, as the
tools do), `templateName` against `templates.yml`, `category` against the schema
enum, and `path` against the docs pages by routed path.

Deliberately not checked: `search:` and `query:` values. They are free text, and
asserting that `search: 'toast'` matches something would pin the ranking rather
than the claim.

Mutations tried, each red: put `ButtonBasic` back; name `B24Carousel`, which has
no page here; name a `Landing` template; put `category: 'forms'` back; put the
directory-only docs path back.
