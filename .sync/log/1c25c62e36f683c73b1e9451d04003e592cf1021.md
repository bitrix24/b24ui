# Port: chore(eslint): lint theme files with `better-tailwindcss`

**Upstream:** `1c25c62e36f683c73b1e9451d04003e592cf1021` (nuxt/ui)
**Decision:** port (partial)

## Upstream change
- `eslint-plugin-better-tailwindcss` goes from `^4.7.0` to `^4.8.0`. The 4.8.0 release lints `export default (options) => ({...})` theme files (schoero/eslint-plugin-better-tailwindcss#397).
- `minimumReleaseAgeExclude` gets the new version.
- `eslint.config.mjs`: `betterTailwindcssConfig(files, entryPoint, { ignore, settings, rules })`, and a new config for `src/theme/**/*.ts`. It uses custom selectors so that only the tv class paths are checked:
  - `base`, `slots`, `variants`, `compoundVariants[n].class`, skipping `*Size` value slots;
  - the `default` export, and a function returning it;
  - `defu(Fn)?` callees.

  `no-concatenated-classes` is turned off, and the entry point is `playgrounds/nuxt/app/assets/css/main.css`.
- The classes this lint flagged upstream were fixed in the previous commit, nuxt/ui@96d0a50.

## b24ui port
- **`pnpm-workspace.yaml`:** catalog `^4.7.0` → `^4.8.0`. The fork has no `minimumReleaseAgeExclude` list (n/a).
- **`pnpm-lock.yaml`:** the same 12-line change as upstream (specifier, version, integrity, two snapshot keys), edited by hand. 4.8.0 has the same dependencies as 4.7.0.
  - `pnpm install --lockfile-only` after the bump re-resolved unrelated peers (+335/−68 lines), so it was not used.
  - `pnpm install --frozen-lockfile` accepts the edited lockfile.
- **`eslint.config.mjs`:** ported as upstream (`getDefaultSelectors` import, `themeClassMatchers`, the options-object helper, the `src/theme` config with the same selectors and rule override, the same entry point). The fork's four existing calls now pass `{ ignore: … }`. Fork-specific additions:
  - **Air hook classes ignored:** `--air`, `--style-*`, `style-*`, `ui-(btn|label|counter)-<size>`, `menu-item-vertical-active`, on top of the existing `AIR_HOOK_CLASSES`. These are plain selectors in `src/runtime/air-design-tokens/**/*.css`, not Tailwind utilities, so no entry point can make them known.
  - **`*Accent` value slots skipped:** the slot/variant lookahead also skips `*Accent`, next to `*Size`. `tooltip.ts` `kbdsAccent: 'default'` holds a Kbd `accent` prop value, not classes.
  - **8 theme files excluded:** they are left out via `ignores` until their classes get a design decision. The TODO in the config lists each one:
    - `avatar.ts`, `listbox.ts`: `text-8.5`, `text-4`, `text-6` are not utilities.
    - `modal.ts`: `backdrop-blur-0.5` is not a utility.
    - `file-upload.ts` (`border-inverted`) and `prose/prompt.ts` (`text-highlighted`): Nuxt UI colors the fork does not define.
    - `dashboard-panel.ts`, `dashboard-sidebar.ts`: contradictory `border-e` / `border-e-0`.
    - `navigation-menu.ts`: undefined `collapsed`.
- **The fork's own lint findings:** `src/theme` gave 662 errors before the ignore list. The obvious typos among them were fixed in a separate fork-only PR (`fix(theme): correct mistyped and redundant classes`), merged before this one: toast `old-style-*`, `ext-(…)`, `:text-(…)`, `ddd-fix-*` markers, and redundant `border-b-1` / `border-t-1`.

The lint runs only after `dev:prepare` (stub `dist`), because the entry point's `@bitrix24/b24ui-nuxt` import resolves `./dist/runtime/index.css`. Without it, fork utilities like `text-description` read as unknown. CI already runs `dev:prepare` before `lint`.
