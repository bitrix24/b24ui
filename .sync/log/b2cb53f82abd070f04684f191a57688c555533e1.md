## Upstream change

Replaces the `playground` job in `.github/workflows/module.yml` with a `consumer`
job, and adds the fixtures it runs against.

The old job installed the pkg.pr.new build of `@nuxt/ui` into
`playgrounds/nuxt` and typechecked it. The new one copies
`test/fixtures/consumer/{full,minimal}` to `$RUNNER_TEMP` — deliberately outside
the checkout, so the root `node_modules` and the workspace cannot leak into
resolution — installs with **no lockfile** (the comment says a fresh resolve is
the only setup that catches missing optional peers), then prepares, typechecks and
builds. `fail-fast: false` keeps the other fixture running when one breaks.

Ten new files carry the two fixtures. The playground's
`typescript.tsConfig.paths` workaround is removed with them: it existed only
because the isolated CI install could not reach `docs/node_modules`, and nothing
installs into the playground any more.

## Why it does not apply

**There is no `.github/workflows/module.yml`.** The workflows here are `ci`,
`deploy`, `npm-publish`, `pr-title`, `release-please`, `release-watchdog` and
`smoke`.

**There is no `test/fixtures/` directory**, so none of the ten added files has a
counterpart.

**The module is tested by a different mechanism.** `test:module` runs
`vitest run --config vitest.module.config.ts` over `test/module/`, which holds
`fixture/` and `module-setup.spec.ts`, and it runs inside `ci.yml` as an ordinary
gate step rather than as a separate workflow against a published preview build.
There is no pkg.pr.new publish here for such a job to consume.

**And the removal half does not apply either.** `playgrounds/nuxt/nuxt.config.ts`
has no `typescript.tsConfig.paths` block — the workaround being deleted was for a
CI install this fork never performs.

## Worth noting

The idea behind the new job — resolve the published package from outside the
workspace, with no lockfile, to catch a missing optional peer — is a real gap that
`test:module` does not cover: it runs against the source tree inside the
workspace. That is a possible improvement to this fork's own testing rather than
a port of this commit, and it is recorded here so the thought is not lost with
the n/a.
