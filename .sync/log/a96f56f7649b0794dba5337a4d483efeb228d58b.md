# Port: feat(components): add `loop` prop (#7128)

**Upstream:** `a96f56f7649b0794dba5337a4d483efeb228d58b` (nuxt/ui)
**Decision:** port

## Upstream change
Reka UI 2.11.0 adds `loop` to `ListboxRootProps` (which `ComboboxRootProps` extends)
and to `TreeRootProps`. With `loop`, keyboard navigation wraps from the last item to
the first and back. Upstream exposes it on every component built on those roots. In
each one, `'loop'` goes into the `Pick<…RootProps, …>` of the props interface and into
the `reactivePick` that feeds `useForwardProps`:
- `CommandPalette.vue` (ListboxRoot)
- `Listbox.vue` (ListboxRoot)
- `InputMenu.vue`, `SelectMenu.vue` (ComboboxRoot)
- `Tree.vue` (TreeRoot)
- `DashboardSearch.vue`, `content/ContentSearch.vue`: picked from `CommandPaletteProps`
  and forwarded to the inner CommandPalette.

No docs, tests or snapshots change upstream.

## b24ui port
- `CommandPalette.vue`, `Listbox.vue`, `InputMenu.vue`, `SelectMenu.vue`,
  `DashboardSearch.vue`, `content/ContentSearch.vue`: the same two one-word insertions
  in each, placed after `highlightOnHover` as upstream does. The fork's lists differ
  only around the insertion point: DashboardSearch and ContentSearch have no
  `loadingIcon` in their picks. This does not affect the change.
- `useForwardProps` here is the fork's proxy-aware one from
  `../composables/useForwardProps`, so a `loop` set through `<B24Theme :props>` or
  `app.config` is forwarded as well.
- Skipped: `Tree.vue`. The fork has no Tree component (see PORTING.md §1).
- No other component in the fork wraps `ListboxRoot`, `ComboboxRoot` or `TreeRoot`.

## Dependency: needs reka-ui 2.11.0
`loop` does not exist in reka-ui 2.10.5, which the fork pins (`pnpm-workspace.yaml`
catalog). This was checked against both published tarballs: in 2.10.5,
`ListboxRootProps` and `TreeRootProps` have no `loop`; in 2.11.0 both have it.
`Pick<ListboxRootProps, … | 'loop'>` therefore fails `typecheck` on 2.10.5.

Upstream bumped the pin in `fa7a9300` (`chore(deps): update reka-ui to v2.11.0`,
#7127). That commit comes before this one and after the ledger cursor (`50cde922`).
This port must merge after that bump. If it is rebased onto a `main` that still pins
2.10.5, the gate fails at `typecheck`.
