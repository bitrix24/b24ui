# port — nuxt/ui@d00e9deeb3de19235f2359c36360068e3557393e

**Upstream:** chore(deps): shorten peer dependency ranges (#6961)

**Decision:** port — cosmetic, and verified to be exactly that.

## Upstream change

Peer ranges drop a `.0.0` that carries no information: `^3.0.0` → `^3`,
`^18.0.0` → `^18`, `^5.6.3 || ^6.0.0 || ^7.0.0` → `^5.6.3 || ^6 || ^7`. Where a
range has a real floor it keeps it — `^2.0.7`, `^4.5.0`, `^3.24.0`, `^1.7.0` are
all untouched.

## What changed here

11 of this fork's 13 peers, the same normalisation. Two are left alone, and for
the same reason upstream leaves its own:

- **`yup: ^1.7.0`** — a real patch floor.
- **`vue: ^3.5.0`** — fork-only (#99), and its floor is *derived*:
  `test/utils/peer-dependencies.spec.ts` computes it from the Vue APIs `src/`
  actually imports, so `^3.5.0` is evidence rather than a number someone typed.
  Shortening it to `^3` would not be cosmetic — it would **lower** the floor and
  re-open the failure that peer exists to close (a consumer on 3.4 satisfies every
  declared constraint, installs cleanly, then hits `useTemplateRef is not a
  function` on first mount).

Upstream has no `@tiptap/*` or `ai` peers to compare against here — those are
dependencies in this fork, a structural divergence `dep-parity` already excludes
by construction.

## Evidence

**Semantic equivalence was checked, not asserted.** Each old range and its new
form were compared with `semver.subset` in **both** directions:

```
  same @inertiajs/vue3  ^2.0.7 || ^3.0.0           -> ^2.0.7 || ^3
  same @nuxt/content    ^3.0.0                     -> ^3
  same typescript       ^5.6.3 || ^6.0.0 || ^7.0.0 -> ^5.6.3 || ^6 || ^7
  …
  all 11 ranges are semantically identical
```

So no consumer's install resolves differently because of this commit.

**The lockfile had to move, and only by the specifier strings.** A peer range is
recorded verbatim in the lockfile's importer block, so `pnpm install
--frozen-lockfile` failed on all seven changed specifiers until the lockfile was
regenerated — which is worth recording, because "cosmetic" reads as "no lockfile
change" and it is not. After `pnpm install --lockfile-only`: 7 insertions, 7
deletions, every one of them a `specifier:` line, and the resolved package set
unchanged at 1773 → 1773, zero added, zero removed.
