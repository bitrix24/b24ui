## One snapshot moves, and it is a fix rather than a regression

`tailwind-merge` `^3.6.0 → ^3.7.0` changed one `DashboardNavbar` snapshot: the
`root` class loses `ps-2 pe-4` and keeps `lg:ps-4 lg:pe-4 … px-8`.

Isolated rather than assumed — pinning `tailwind-merge` back to `3.6.0` with
every other bump applied makes the suite pass again, so the bump is the cause.

It is the **correct** new behaviour. The theme gives
`ps-2 pe-4 lg:ps-4 lg:pe-4` and the test passes `class="px-8"`. `px-8` sets
padding-left and padding-right; `ps-2`/`pe-4` set padding-inline-start/end,
which are the same physical properties at the same breakpoint. They conflict,
and the caller's class is meant to win — that is what `tailwind-merge` is for.
3.6.0 did not see the conflict and emitted both, leaving which one applied to
CSS source order rather than to the caller. 3.7.0 resolves it.

The `lg:` variants survive because `px-8` has no `lg:` counterpart to conflict
with, which is also right.

Blast radius measured, not guessed: **one** snapshot out of the whole corpus
moves, so in practice this reaches components whose theme mixes logical padding
with a caller passing physical `px-*`. Accepted rather than pinned back.
