## The claim, checked against this fork's component

Upstream's note asserts two things. Both hold here verbatim, and both were read
out of `src/runtime/components/NavigationMenu.vue` rather than assumed from the
upstream wording:

**1. Vertical and not collapsed → children render recursively as items, styled
by `link`.** The `AccordionContent` block is gated on exactly that condition and
re-enters the item template one level down:

```vue
<AccordionContent v-if="props.orientation === 'vertical' && item.children?.length && !props.collapsed">
  <AccordionRoot …>
    <ReuseItemTemplate v-for="(childItem, childIndex) in getChildren(item)" :level="level + 1" … />
```

`ReuseItemTemplate` renders each child through the same `B24LinkBase` that
styles a top-level item, with `b24ui.link({ …, level: level > 0 })`.

**2. `childLink` only reaches horizontal `content` and the collapsed popover.**
There are exactly two `data-slot="childLink"` sites in the file, and each sits
under one of those gates:

| site | gate |
| --- | --- |
| inside `<NavigationMenuContent>` | `props.orientation === 'horizontal' && (item.children?.length \|\| …item-content slot)` |
| inside the popover body | `props.orientation === 'vertical' && props.collapsed && item.children?.length && (!!props.popover \|\| !!item.popover)` |

Nothing else in the template calls `b24ui.childLink`.
