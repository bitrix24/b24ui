# Port: perf(DashboardSearch/ContentSearch): lazy load modal and command palette

**Upstream:** `6f50933451bfa1150a303378682f5282c04820d7` (nuxt/ui, #7161)
**Decision:** port — with the prerequisite infrastructure from `691899a8` carried in

## Upstream change

`DashboardSearch` and `ContentSearch` stop importing `Modal` and
`CommandPalette` statically. `Modal` comes from the shared `lazyOverlays.modal`
async component, `CommandPalette` from `defineAsyncComponent(() => import(...))`,
and the whole `<Modal>` is gated by `v-if="renderModal"`, where
`useLazyOverlay(open, preload)` turns `true` the first time the search opens (or
immediately with `unmountOnHide: false`, which must keep content mounted) and
preloads both chunks on idle after mount. `ContentSearch` also treats a bound
`open` attr (it has no `open` prop; `open` comes from `useContentSearch()`) as
open. Tests await `vi.dynamicImportSettled()` before snapshotting and add
"mounts once opened" / "mounts before opening with `unmountOnHide: false`" cases.

## b24ui port

Applied 1:1 with `U*` → `B24*` local names (`B24Modal`, `B24CommandPalette`),
so the template is unchanged apart from the `v-if`.

**Prerequisite not yet ported.** `useLazyOverlay` and `utils/lazy-overlay` are
introduced by `691899a8` (Header/DashboardSidebar/Sidebar lazy menu overlay),
which sits two commits earlier and is not in this fork yet. To keep this port
self-contained, `src/runtime/composables/useLazyOverlay.ts`,
`src/runtime/utils/lazy-overlay.ts` and `test/composables/useLazyOverlay.spec.ts`
are copied verbatim from `691899a8` (they need no b24ui rewrite; the fork's
`utils/prefetch.ts` already exports `requestIdleCallback`/`cancelIdleCallback`).
When `691899a8` is ported, those three files will already match and only its
component/test hunks remain.

**Not touched:** `DashboardSearch.vue` still imports `useForwardProps` from
`reka-ui` rather than the fork's proxy-aware composable — pre-existing, outside
this commit's scope.

## Two build adapters

Component detection (`src/utils/components.ts`, shared by `src/module.ts` and
`src/unplugin.ts`) builds its graph by matching `B24<Name>` identifiers in each
component file. Both files still reference `B24Modal`/`B24CommandPalette` (as
locals and in the template), so `Modal` and `CommandPalette` stay detected in
both adapters. The dynamic `import()`s are relative to the component file, so
they resolve from `runtimeDir` in either build; no adapter change is needed.

## Tests

Upstream's test edits ported to `DashboardSearch.spec.ts` and
`content/ContentSearch.spec.ts`; `useLazyOverlay.spec.ts` added. Snapshots not
regenerated in this run: `DashboardSearch.spec.ts.snap`,
`DashboardSearch-vue.spec.ts.snap`, `content/ContentSearch.spec.ts.snap` are
expected to change (upstream's did — async component placeholders / ordering).
