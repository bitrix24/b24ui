## Upstream change

no snapshots.

## b24ui port

## The companion change upstream has no need for

`pnpm-workspace.yaml` carries an override upstream does not:

```yaml
  # Keeps a single prosemirror line: every @tiptap/* package peer-accepts a range
  # of pm versions, so without this pnpm can resolve a second copy and ProseMirror
  # state instances stop being `instanceof` across the boundary. Keep in step with
  # the @tiptap/* family version in package.json.
  '@tiptap/pm': ^3.30.2
```

Its last sentence is an instruction, and this is the commit that triggers it: the
family moved, so the override moves with it to `^3.30.5`. Left at `^3.30.2` it
would still have *resolved* — the range is open — but the pin would no longer be
saying what it means, and the next person to read it would find it disagreeing
with the manifest it claims to track.

Verified rather than assumed: after install, `pnpm-lock.yaml` holds exactly one
`@tiptap/pm@3.30.5`. A second prosemirror line is the failure this override
exists to prevent, so a single entry is the assertion that matters.
