# port — nuxt/ui@8e4546e3b775ce91a8a2f9198cc70f9f94158bc1

**Upstream:** fix(InputDate/InputTime): emit focus and blur when focus enters or
leaves the field (#6855)

**Decision:** port — both components are here with the identical handlers.

## The defect

A date field is several focusable segments (day, month, year). `@blur` and
`@focus` fire on **each** of them, so moving from the day to the month emitted a
`blur` followed by a `focus` — and a form validating on blur ran mid-entry, on a
value the user had not finished typing.

## The fix

`@blur`/`@focus` become `@focusout`/`@focusin` — which bubble — with a containment
guard that ignores movement inside the field:

```ts
if (event.relatedTarget && (event.currentTarget as HTMLElement).contains(event.relatedTarget as Node)) {
  return
}
```

Applied to both `InputDate.vue` and `InputTime.vue`. `emits(...)` now precedes
`emitForm*()`, matching upstream's order.

`test/utils/form.ts` gains `B24InputDate` and `B24InputTime` in both its import
and its `components` map, so `renderForm` can mount them.

## Mutations — each half independently pinned

| mutation | fails |
| --- | --- |
| drop the containment guard, keep `focusin`/`focusout` | `…not between segments` and `validate on blur ignores focus moving between segments` |
| revert the listeners to `@blur`/`@focus`, keep the guard | `focus and blur events…` and `validate on blur works` |

Different tests for different halves, which is what makes a failure addressable.

## One subtlety carried over from upstream's tests

Each test resets the fake clock before dispatching:

```ts
// Vue skips native events stamped at the exact time their listener was attached
vi.setSystemTime(new Date(date.getTime() + 1000))
```

with an `afterEach` restoring it. Without that the dispatched events are silently
ignored and the tests pass for the wrong reason. Worth knowing before anyone
"simplifies" the clock handling out.
