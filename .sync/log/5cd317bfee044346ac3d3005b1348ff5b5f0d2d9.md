# Port: fix(Drawer): emit `after:leave` and `after:enter` when the animation ends (#7107)

**Upstream:** `5cd317bfee044346ac3d3005b1348ff5b5f0d2d9` (nuxt/ui)
**Decision:** port — direct 1:1

## Upstream change
Unlike Modal and Slideover, Drawer never emitted `after:leave` / `after:enter`. `OverlayProvider` waits for `after:leave` to unmount a programmatic overlay, so a Drawer opened through `useOverlay` was never cleaned up.

The fix:
- adds `'after:leave' | 'after:enter'` to `DrawerEmits`;
- binds `@animation-end="onAnimationEnd"` on the vaul root;
- emits `after:enter` on `animationEnd(true)`, and `after:leave` on `animationEnd(false)` only after a real open. vaul also fires `animationEnd(false)` when a closed drawer mounts.

A spec test covers it, and `use-overlay.md` now lists Drawer among the supported overlays.

## b24ui port
- `src/runtime/components/Drawer.vue`: ported verbatim (emit types, `entered` flag + `onAnimationEnd`, `@animation-end` on the root `<component>`).
  - The fork forwards the root emits through `useForwardProps(…, useBlurOnOpen(() => props.open, emits))`, which wraps only `update:open`.
  - The forwarded `onAnimationEnd` and the new `@animation-end` listener are merged by Vue, so consumers still receive `animationEnd` as before.
- `test/components/Drawer.spec.ts`: the new test is added verbatim at the end, with `vi` added to the vitest import.
- `docs/content/docs/3.composables/use-overlay.md`: the intro sentence now includes `[Drawer](/docs/components/drawer/)`, with the fork's trailing-slash link style. The fork's `OverlayProvider` relies on `@after:leave` the same way, so the claim holds here.
