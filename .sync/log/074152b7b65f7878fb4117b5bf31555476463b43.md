# port — nuxt/ui@074152b7b65f7878fb4117b5bf31555476463b43

**Upstream:** fix(Link): propagate click handler errors to Vue error handling (#6993)

**Decision:** port — both files match upstream's pre-image exactly.

## The defect

`onClickWrapper` called each handler and **dropped what it returned**. A handler
that rejects therefore produced an unhandled rejection instead of reaching Vue,
so `onErrorCaptured` never saw it.

With `loading-auto` it also stranded the button: the spinner is cleared when the
click settles, and nothing was telling it that it had.

## The fix

Collect the return values and hand them back:

```ts
const results: unknown[] = []
…
results.push(onClick(e))
…
return Promise.all(results)
```

Applied to both `LinkBase.vue` and the Inertia override, as upstream does.

## b24ui adaptation

Upstream's Button test reads the loading state through
`findComponent({ name: 'Icon' })`. **This fork has no `Icon` component** — the
existing `with loading-auto works` test carries that same assertion commented
out for exactly this reason. The port reads `data-slot="baseLoading"` instead,
and that marker was probed first rather than assumed: present while a
`loading-auto` click is pending, absent once it settles. An assertion on a
marker that is never there would have passed for the wrong reason.

`ULink` → `B24Link`.

## Coverage, and one place it is absent

| mutation | red |
| --- | --- |
| revert the whole change in `LinkBase.vue` | both the sync and the async cases |
| keep the collection but drop `return Promise.all(results)` | **only** the async cases |

The difference is the interesting part. A synchronous `throw` reaches Vue
through the handler call itself, with or without the return — what catches it in
the sync case is the *second* assertion, that `loading-auto` has cleared. Only
the async path needs the returned promise. So the two assertions are not
redundant; each covers a different half.

**The Inertia override is not covered.** No test mounts it: exercising it needs
`@inertiajs/vue3` and a build configured with `router: 'inertia'`, and the one
spec that mentions inertia — `vue-stub-imports.spec.ts` — checks that the stubs
export every name the runtime imports, not any behaviour. The change there is
character-identical to the one in `LinkBase.vue` and is type-checked by
`vue-tsc`, but nothing runs it. Said here rather than left to look covered.
