# port — nuxt/ui@36d55434138df49c8da5b59f7e5aa9d89113e27c

**Upstream:** chore(vscode): scope Tailwind classRegex to default export objects

**Decision:** port — the pre-image is byte-identical here and the problem is the
same, but applying the diff verbatim would have cost this fork 29 real class
strings that upstream's tree does not have.

## Upstream change

One line in `.vscode/settings.json`. `tailwindCSS.experimental.classRegex` grows
from a bare extraction pattern to the two-element container form:

```diff
-    ["[:\\[,]\\s*['\"`]([^'\"`]*)['\"`]"]
+    ["export default[^{]*\\{([\\s\\S]*)\\}", "[:\\[,]\\s*['\"`]([^'\"`]*)['\"`]"]
```

The first pattern picks the container — the default-export object — and the
second extracts class strings only inside it. Before, any string after `:`, `[`
or `,` anywhere in the file was offered as a Tailwind class: imports, JSDoc
prose, size keys.

## Why it is not verbatim here

Our `.vscode/settings.json` carries the pre-image exactly, so the diff *applies*.
Measuring what it does was the point.

Across all 120 `src/theme/*.ts`, upstream's single entry drops class strings in
seven files. Four of those are real losses:

| File | Strings lost | Where they live |
| --- | --- | --- |
| `field-group.ts` | 19 | `export const fieldGroupVariant` / `fieldGroupVariantWithRoot` |
| `calendar.ts` | 8 | `const daySizes` |
| `button.ts` | 1 | `const safeList` |
| `slideover.ts` | 1 | a top-level `const` |

All four declare classes in a top-level `const` **before** `export default`, so
the container never reaches them. `fieldGroupVariant` is not incidental — it is
imported by `button.ts` and is fork structure.

So this port keeps upstream's entry and adds a second one for that shape:

```
["\\n((?:export )?const [\\s\\S]*)\\nexport default", "[:\\[,]\\s*['\"`]([^'\"`]*)['\"`]"]
```

`(?:export )?` is required, not defensive: `field-group.ts` — the file with 19 of
the 29 — uses `export const`, and without it that file stays uncovered. The
container is bounded at `\nexport default` rather than left open to EOF; an
unbounded variant was measured too and recovered nothing extra, so the tighter
one is used.

## Evidence

Both patterns were run in Node against every `src/theme/*.ts`, comparing three
sets per file: every string the old bare pattern matched, what upstream's entry
matches, and what both entries together match.

**Nothing real is lost.** With both entries, the only strings excluded anywhere
in the 120 files are:

- `calendar.ts` — a JSDoc fragment (`" half is the scale as it was, so nothing
  changes on a pointer\n * device.\n */\nconst daySizes = {\n  xs: "`)
- `editor-suggestion-menu.ts` — `'ms-[4px] ...'` from a `@memo` comment on line 6;
  the real `ms-[4px] flex-1 flex flex-col text-start min-w-0` on line 63 is inside
  the export and still covered
- `chip.ts` — the size keys `2xs`, `xs`, `xl`, `2xl`
- `toast.ts` — the prose `"Content message"` and `"Action"`

That list *is* the upstream commit's stated target. The narrowing does what it
was written to do, and nothing else.

**The recovery is measured, not assumed.** Upstream's entry alone leaves 29
strings in 4 files uncovered; with the second entry the count is 0.

## Scope of the change

Editor-only. `tailwindCSS.*` settings are read by the VS Code Tailwind extension
and by nothing in this repo — the one hit for `.vscode/settings.json` in the tree
is `src/theme/prose/code-icon.ts:12`, a filename-to-icon mapping. No build, test
or lint step parses this file, so the gate cannot confirm the change; the Node
measurement above is the evidence, and it is the only kind available.

The file is now JSONC rather than strict JSON. VS Code's own settings format
allows comments, and nothing here parses it, so this is safe — the divergence
from upstream needed its reason at the site.
