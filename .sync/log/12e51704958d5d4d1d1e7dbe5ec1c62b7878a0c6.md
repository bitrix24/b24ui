# skip — nuxt/ui@12e51704958d5d4d1d1e7dbe5ec1c62b7878a0c6

**Upstream:** chore(github): report bundle size on pull requests (#7032)

**Decision:** skip. Nothing it adds ships in the package; adopting it is a
separate piece of CI work, not a port.

## What it adds

35 files, +825/−23, all repository tooling:

- `test/bundle/` — five fixture apps (`nuxt`, `nuxt-full`, `nuxt-detection`,
  `vue`, `vue-detection`) plus `build.mjs` / `size.mjs` / `compare.mjs`, and a
  `pnpm run size` script;
- `pnpm-workspace.yaml` gains `test/bundle/*`, so each fixture becomes a
  workspace package (`pnpm-lock.yaml` +133 lines);
- `.github/workflows/bundle-size.yml` — builds base and head on
  `pull_request` to branches `v4` and `v5`;
- `.github/workflows/bundle-size-comment.yml` — a `workflow_run` job holding
  `pull-requests: write` that downloads the first workflow's artifact (built
  from the untrusted pull request) and posts a comment;
- one-line mentions in `AGENTS.md` and `.github/contributing/testing.md`, and a
  `tsconfig.json` exclude for the fixtures' `dist/`.

## Why not here, checked

- **None of it reaches consumers.** `package.json` `files` publishes `dist/`,
  `.nuxt/b24ui.static.css`, `vue-plugin.d.ts`, README and LICENSE; no `src/`
  file changes.
- **It would not run as written.** `bundle-size.yml` triggers on pull requests
  to `v4`/`v5`; this fork's default and only release branch is `main`, so the
  workflow would be inert until rewritten.
- **The fixtures are upstream's.** They import `@nuxt/ui` / `@nuxt/ui/vite`
  and `@import "@nuxt/ui"`; the fork's package, module key (`b24ui`) and
  entries differ, so each fixture would need rewriting rather than copying.
- **It adds a privileged workflow.** Upstream validates the artifact before use
  (single artifact, < 1 MB), but a `workflow_run` job with
  `pull-requests: write` acting on pull-request-produced data is exactly the
  kind of change that deserves its own review here, not a ride-along in a sync
  batch.
- **It adds five workspace packages to the install graph**, which is a
  dependency-surface change of its own.

If bundle-size reporting is wanted, it is a self-contained task: adapt the
fixtures to `@bitrix24/b24ui-nuxt`, retarget the workflow at `main`, and
review the `workflow_run` permissions on their own merits.
