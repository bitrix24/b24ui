# Port: docs: resolve icon load failures during prerender

**Upstream:** `08e753174f634400190d8dc0a36dbd3471d1f5e5` (nuxt/ui, #6844)
**Decision:** port — one of two halves; the other does not exist here

## Upstream change

Four files, and the diffstat is misleading in both directions.

**`docs/nuxt.config.ts` + `docs/package.json` + `pnpm-lock.yaml` — the actual
fix.** `ProseCodeIcon` resolves through the code icon map and falls back to
`i-vscode-icons-file-type-{extension}`; `ProsePrompt` hardcodes a logo per
action. Neither appears in anything `clientBundle.scan` looks at, so both were
left to runtime icon loading — which is broken during SSR (nuxt/icon#518). The
fix lists the icons by hand in `clientBundle.icons` until nuxt/icon#527 lands.

**`src/theme/prose/code-icon.ts` — 98 lines of diff and no change.** The map is
re-sorted alphabetically. Verified as multisets rather than eyeballed: 65
key→value pairs before, 65 after, identical.

## b24ui port

**The fix half is not applicable.** Our docs have no `@nuxt/icon` and no
`clientBundle` — grepped `docs/nuxt.config.ts` and `docs/package.json` for
both, no matches. Icons here are `@bitrix24/b24icons-vue` Vue components,
imported and bundled by the compiler, so there is no runtime icon resolution to
fail during prerender. The whole class of bug the commit fixes cannot occur in
this fork.

**The reorder half is applied.** Our `code-icon.ts` holds the same map with
b24icon component names in place of iconify strings, and was in upstream's old
order. Sorting it brings the file back into structural parity, which is the
thing that makes the next port of this file a clean diff — the sync workflow
leans on comparing our file against upstream's pre-image, and an unrelated
ordering difference is exactly what makes that comparison useless.

Safe because the map is a lookup, not a sequence: `CodeIcon.vue:89` reads
`icons.value[name.toLowerCase()] ?? icons.value[extension] ?? 'TerminalIcon'`,
so no first-match-wins behaviour depends on key order.

Verified as a pure permutation: 64 key→value pairs before and after, identical
as sets, and the resulting key order equals upstream's exactly.

## The one remaining difference: `deno`

Upstream has 65 keys, we have 64. The missing one is
`'deno': 'i-vscode-icons-file-type-deno'`.

This is **not a gap to fill**: `@bitrix24/b24icons-vue` ships no Deno glyph —
its `file-type` set has 42 icons and Deno is not among them. The key cannot be
mapped until the icon package adds one, so the absence is a constraint of the
icon set rather than an oversight in the map. With the sort applied it is now
the only structural difference between the two files.
