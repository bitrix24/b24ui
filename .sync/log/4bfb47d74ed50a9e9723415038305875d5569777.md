# port — nuxt/ui@4bfb47d74ed50a9e9723415038305875d5569777

**Upstream:** chore(cli): register new components in `ThemeDefaults` again

**Decision:** port — verbatim. `cli/commands/make/component.mjs` and
`appendThemeDefault` in `cli/utils.mjs` matched upstream's parent byte for byte,
and `git apply` took the patch unchanged.

## The defect — here as upstream

`pnpm cli make component` registers the new component in `ThemeDefaults` so
`<B24Theme :props>` autocompletes it. It wrote to
`src/runtime/composables/useComponentProps.ts`. That file has no `ThemeDefaults`
interface — `grep -c 'export interface ThemeDefaults'` gives 0 there and 1 in
`src/runtime/types/theme.ts` — so the regex missed and the function hit
`if (!match) return`. **Every component scaffolded since the interface moved
silently skipped step 5 of AGENTS.md's workflow.**

## The half that matters more here

The fix also replaces the insertion. The old body was:

```js
const sorted = [...body.split('\n'), entry].sort().join('\n')
```

— a lexical sort of **every line** of the interface body. Run against this
fork's real `types/theme.ts` (a copy, in a scratch dir), with the path fixed and
the old body kept:

- it moves **67 of the body's 172 lines** (diff: 67 removed, 68 added);
- the commented-out entries (`// authForm?:`, `// carousel?:` … upstream
  components this fork does not have) sort to the top, away from their place;
- the three-line `// TODO` that documents `form?:`'s loosened generics is
  separated from it;
- the 4-space-indented entries of the nested `prose?: { … }` block sort ahead of
  every 2-space line and land at the top of the interface — so
  `radioGroup`, `range`, `scrollArea`, … `tooltip`, `user` end up **inside**
  `prose?: {}`.

The result still parses. It would have silently changed the shape of
`ThemeDefaults` for every component after `prose` alphabetically.

**The wrong path was the only thing preventing that.** Fixing the path without
the new insertion would have turned a silent no-op into silent corruption — so
the two halves are one change here, not two.

The new body inserts the entry before the first top-level (`^ {2}\w+\?:`) line
that sorts after it, and walks back over comment lines so a comment stays with
the entry it documents; if the interface is missing it now says so. Measured on
the same copy: exactly **1** line added for `carousel`, `formGroup` and
`zoomPanel`, each in the right place.

## Beyond upstream

`.github/contributing/component-structure.md:478` stated the same stale path,
and that *"the CLI scaffolder auto-inserts the entry"* — false until this
commit. Corrected to `src/runtime/types/theme.ts`. Upstream still carries the
old line at `v4`'s tip. (`AGENTS.md`'s copy of the path was fixed in #634, from
nuxt/ui@9809cfe.)

## Coverage

Upstream ships no test, and nothing here tested the CLI at all — which is how
this lived unnoticed. New `test/utils/cli-theme-defaults.spec.ts`, run against a
temp copy of the real `types/theme.ts`:

| mutation | red |
| --- | --- |
| path in `component.mjs` reverted | `writes to the file that declares the interface` |
| `appendThemeDefault` reverted to the old sort | `inserts exactly one line…`, `keeps the prose block intact`, `puts a new key ahead of the comments…`, `says so, and writes nothing…` |
| comment walk-back removed | `puts a new key ahead of the comments…` |
| duplicate check removed | `is idempotent` |

Every case is red under at least one mutation. `is idempotent` stays green
under the old sort, correctly — the old body was idempotent too — which is why
it got its own mutation. The first case reads the path out of `component.mjs`
and checks that file for the interface, so it also catches the interface moving
again, not only this regression.
