# port — nuxt/ui@db45a3ecdf3e9d8c9b5002573292df7c5e63c29e

**Upstream:** chore(cli): stop shipping the cli in the package (#6959)

**Decision:** port — the same scaffolder is published here for no reason, and the
same `npm link` step can go with it.

## Upstream change

The CLI stops being a published binary:

- `bin: { "nuxt-ui": "./cli/index.mjs" }` removed
- `"cli"` removed from `files`
- `"cli": "node ./cli/index.mjs"` added to `scripts`

and every doc switches from `nuxt-ui make …` (which needed a global `npm link`
first) to `pnpm cli make …`.

## What changed here

The same three edits to `package.json`, with `bitrix24-ui` as the bin name, plus
the two contributor docs that quote the command:

- `AGENTS.md` — the `npm link` one-time-setup block is gone; `bitrix24-ui make
  component` → `pnpm cli make component`, in the instructions and in the
  new-component checklist.
- `.github/contributing/component-structure.md` — the same rename in the
  `ThemeDefaults` section.

The diff shape matches upstream's line for line: `package.json` 5 +----,
`AGENTS.md` 12 +++---------.

## Not applicable

Two of upstream's five files have no counterpart here:

- `docs/app/components/content/SupportedLanguages.vue` does not exist.
- `docs/content/docs/1.getting-started/4.contribution.md` exists but has **no CLI
  section** — a grep for `make component` or `make locale` across `docs/` returns
  nothing. This fork never documented the CLI to readers of the site.

That second one also answers the question worth asking before removing a `bin`:
**does dropping it break a consumer?** No. The CLI writes to `src/runtime/components/`,
`src/theme/` and `docs/content/docs/2.components/` (`cli/templates.mjs:47`, `:158`,
`:218`) — repository-relative paths that mean nothing inside somebody else's
`node_modules`. It is a contributor scaffolder, it is referenced only from
`AGENTS.md` and `.github/contributing/`, and the published docs never mention it.

## Evidence

**Against the packed tarball, not the manifest.** `npm pack --dry-run --json`
after the change reports **802 files, zero under `cli/`**, `bin: null`, and
top-level entries of exactly `.nuxt`, `LICENSE`, `README.md`, `dist`,
`package.json`, `vue-plugin.d.ts`. Seven files and 14 087 bytes stop shipping:
`cli/index.mjs`, `cli/package.json`, `cli/templates.mjs`, `cli/utils.mjs`,
`cli/commands/make/{index,component,locale}.mjs`.

**The CLI still runs.** `pnpm cli --help` prints the command tree, so the
scaffolder is intact for contributors — only its packaging changed.

**Mutation — the new prose is pinned.** `test/utils/documented-scripts.spec.ts`
asserts that every `pnpm <script>` quoted in the contributor docs is a script
`package.json` defines. Renaming the new script to `cli-x` turns both edited files
red — `AGENTS.md quotes only scripts that exist` and
`.github/contributing/component-structure.md quotes only scripts that exist`, with
`expected [ 'cli' ] to deeply equal []`. So the two docs are held to the script
existing, in both test environments. Without that check the rename could have left
the docs quoting a command that does not run, which is the exact failure that
spec's docblock says it was written for.
