# Port: docs(showcase): add kleinezeitung.at

**Upstream:** `f6d188bd785d40f2a2d721e3400091cc19cee236` (nuxt/ui)
**Decision:** port — the schema half; the content half is a no-op

## Upstream change

Another showcase entry, plus the reason it needed more than two lines: the site
requires a wider viewport, a delay, and an element removed before the screenshot
is usable. So `screenshotOptions` gained three keys and `delay` became optional.

```diff
         screenshotOptions: z.object({
-          delay: z.number()
+          delay: z.number().optional(),
+          width: z.number().optional(),
+          cookies: z.array(z.string()).optional(),
+          removeElements: z.array(z.string()).optional()
         }).optional()
```

## b24ui port

**Content half — no-op.** Same reasoning as `cf5f15e3`: our showcase lists
projects built with Bitrix24 UI.

**Schema half — ported.** It is not decorative here. `docs/modules/showcase.ts`
reads `screenshotOptions` and spreads it straight into `capture-website`, so the
three new keys reach the screenshotter as soon as the schema stops rejecting
them. The old schema also *required* `delay`, so an entry wanting only `width`
would have failed validation.

## Deviation: `delay` was inert in this fork

Found while checking that the widened schema would actually do something. Our
module hardcoded the delay **after** the spread:

```ts
...(template.screenshotOptions || {}),
delay: 2,
```

so a per-entry `delay` was overwritten every time. Upstream has no default there
at all, which is why their schema could treat `delay` as the one real option.

Porting the widening as-is would have shipped a schema advertising an option the
module discards — the same shape of false claim as the MCP `inputExamples` that
named examples which did not exist. The fork's 2-second default is worth
keeping, so it moved **before** the spread: still a default, now overridable.

One line, and it is a deviation from the upstream commit rather than part of it,
which is why it is recorded here rather than folded into the port.

No entry in `docs/content/showcase.yml` sets `screenshotOptions` today, so
nothing changes behaviourally right now — the point is that the schema and the
module now agree.
