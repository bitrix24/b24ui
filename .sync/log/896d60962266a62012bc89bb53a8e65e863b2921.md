# Port: perf(components): import Reka UI primitives by name instead of from `reka-ui/namespaced` (#7176)

**Upstream:** `896d60962266a62012bc89bb53a8e65e863b2921` (nuxt/ui)
**Decision:** ported

## Upstream change
Seven components stop importing namespace objects from `reka-ui/namespaced`
(which pulls in every primitive of each namespace and defeats tree-shaking).
Each imports the individual primitives by name from `reka-ui` and rebuilds a
local object with the same shape (`const Popover = { Root: PopoverRoot, … }`),
so templates (`<Popover.Root>` etc.) are untouched. Files: `Calendar.vue`,
`ContextMenuContent.vue`, `DropdownMenuContent.vue`, `InputDate.vue`,
`InputMenu.vue`, `InputTime.vue`, `Popover.vue`. No build, test or lint changes.

## b24ui port
Same seven files (the only `reka-ui/namespaced` users in b24ui's `src/`; no
fork-only component uses it). Upstream's import line and local-object consts
copied verbatim; the patch did not apply textually because of fork drift
(`B24*` component imports, `icons` dictionary, missing `useForwardProps` /
`onScopeDispose` / `useAttrs` imports), so each hunk was applied by hand:
- `ContextMenuContent.vue`: the separate `useForwardPropsEmits` import merges
  into the new line, as upstream.
- `DropdownMenuContent.vue`: the fork has no `useForwardPropsEmits` import; its
  separate `import { DropdownMenuArrow } from 'reka-ui'` is merged into the new
  named import instead.
- `InputMenu.vue`: Combobox/Autocomplete names appended to the existing
  `TagsInput*` import, as upstream.
- Consts placed after the last script-setup import, before `defineOptions` /
  `defineProps`.

All imported names verified present in the pinned `reka-ui@2.11.0`
(PORTING.md §2 pin untouched). Templates unchanged, so rendered output and
snapshots should be identical.
