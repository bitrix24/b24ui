# port — nuxt/ui@f4322e7a3577939f43be0781170a4827af15122c

**Upstream:** fix(FileUpload): make the `dropzone` prop reactive (#7055)

**Decision:** port

## Problem
`useFileUpload` read `dropzone` once in `onMounted`, so toggling the
`dropzone` prop on `B24FileUpload` after mount neither attached nor detached the
drop zone; disabling it mid-drag also left `isDragging` stuck on.

## Change
- **src/runtime/composables/useFileUpload.ts** — `dropzone` option is now
  `MaybeRef<boolean>`; a watcher (`immediate`) creates `useDropZone` in a fresh
  `effectScope` per enable and, on cleanup, stops the scope and resets
  `isDragging`.
- **src/runtime/components/FileUpload.vue** — passes
  `toRef(() => props.dropzone)` instead of the raw value.
- **test/components/FileUpload.spec.ts** — `dropzone` block: enable/disable
  after mount, drag state cleared mid-drag.
- **test/composables/useFileUpload.spec.ts** — drop zone registers once a ref
  turns true; `isDragging` drops when disabled mid-drag.

## Adaptations
- Fork keeps its JSDoc on `useFileUpload`; the `options.dropzone` entry now
  notes it is reactive.
- `props` is the `useComponentProps` proxy, so `toRef(() => props.dropzone)`
  also tracks `<B24Theme :props>` defaults.
