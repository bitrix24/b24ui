# Port: docs(server): migrate to `nuxt/server` (#7157)

**Upstream:** `9c4e33b7e076aa6bd59b5bd99d8621d9dc1bcf60` (nuxt/ui)
**Decision:** port (docs-only, no `src/` change)

## Upstream change
The docs server code stops relying on Nitro auto-imports and imports each helper
explicitly: `defineEventHandler` / `createError` / `readBody` from `nuxt/server`
(new in Nuxt 4.6) or `h3`; `defineMcp*` from `@nuxtjs/mcp-toolkit/server`;
`useEvent` / `defineNitroPlugin` from `nitropack/runtime`. `eventHandler` becomes
`defineEventHandler`. `component-example.get.ts` takes the h3 v2 / Nuxt 4.6 shapes:
`event.res.headers.append(...)` replaces `appendHeader`, and `createError` gets
`status` / `statusText` instead of `statusCode` / `statusMessage`.
`nitro.prerender.{routes,crawlLinks}` moves to the top-level `prerender` option
(the nitro keys are deprecated in `@nuxt/schema` 4.6). It also reverts a
`PageHero.vue` CSS tweak and edits the AI routes and the playground `server/api/`.

## b24ui port
The fork is on Nuxt `^4.6.0`, whose `nuxt/server` export exists, so it applies.
- `docs/nuxt.config.ts`: `routes` and `crawlLinks` move to top-level `prerender`.
  `autoSubfolderIndex: false` stays under `nitro.prerender`; the top-level
  `PrerenderOptions` has no such key.
- `docs/server/api/component-example.get.ts`: same as upstream.
- `docs/server/api/{countries,locales,phone-codes}.json.get.ts`: import from
  `nuxt/server`, `eventHandler` becomes `defineEventHandler`.
- `docs/server/api/navigation.json.get.ts`, `docs/server/mcp/index.ts`: `h3` imports, as upstream.
- `docs/server/mcp/{prompts,resources,tools}/b24-ui-*.ts`: explicit `defineMcp*`,
  `useEvent` and `createError` imports, added only where the file uses them.
- `docs/server/plugins/llms.ts`: `defineNitroPlugin` import.

## Divergences / n/a
- `ai`/`chat`/`completion` routes, `server/utils/chatUser.ts` and playground
  `server/api/`: n/a, since the fork has no AI chat (PORTING §2).
- `fonts`, `github/*`, `module.json` routes, `openapi.json`, `agent-discovery`,
  `utils/releases.ts`, `PageHero.vue`, `setup-project-with-template` prompt and
  `templates` resource: not in the fork.
- Upstream's added `SITE_URL` / utility imports: the fork uses
  `useRuntimeConfig()` (still auto-imported) and `~~/server/utils/*` imports, so it
  keeps those.
- Fork-only routes (`routes/sitemap*`, `routes/raw/*`, `.well-known/*`) are left as
  they are, because upstream has no counterpart change for them.

No dependency or lockfile change.
