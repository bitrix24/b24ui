# Port: fix(Tree): use logical padding for indentation

**Upstream:** `958a3ba55763a282d28829385490b963c1087e37` (nuxt/ui, #6815)
**Decision:** port — the half that exists here

## Upstream change
Two inline styles switch from a physical to a logical property, so tree
indentation grows from the reading edge instead of always from the left:

```diff
-  paddingLeft: `${row.depth}rem`
+  paddingInlineStart: `${row.depth}rem`
```

in `docs/.../examples/table/TableTreeDataExample.vue`, and the same rewrite on
`Tree.vue`'s `flattenedPaddingFormula(level)` style binding.

## b24ui port
**The component half does not apply** — b24ui has no `Tree` component
(`src/runtime/components/Tree.vue` does not exist, and neither does
`src/theme/tree.ts`).

**The docs half does**, and carried the identical defect:
`docs/app/components/content/examples/table/TableTreeDataExample.vue:109` built
its depth indent with `paddingLeft`. Under an RTL locale the rows would indent
away from the text, i.e. the hierarchy reads backwards. Fixed.

Checked the class rather than only the file upstream touched: grep for
`paddingLeft` / `padding-left` across `src/` finds nothing but
`--ui-btn-padding-left`, which is a **CSS variable name** consumed by logical
`ps-`/`pe-` utilities in `src/theme/button.ts` — already correct, and renaming
the variable would be churn.

This matters here rather than being theoretical: b24ui ships an `ar` locale with
`dir: 'rtl'`.
