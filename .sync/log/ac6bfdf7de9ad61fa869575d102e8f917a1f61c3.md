# Port: docs(nuxt.config): silence jiti fallback warnings (#7135)

**Upstream:** `ac6bfdf7de9ad61fa869575d102e8f917a1f61c3` (nuxt/ui)
**Decision:** port (partial)

## Upstream change
Nuxt 4.6 tries to load `nuxt.config.ts` natively first. If that fails, it falls
back to jiti and warns `NUXT_B5023`. Upstream makes its docs config load natively:
- `docs/nuxt.config.ts`: the `package.json` import gets `with { type: 'json' }`.
  The two `./server/utils/*` imports get explicit `.ts` extensions.
- `docs/server/utils/llms.ts`: its `./site` import gets an explicit `.ts`.
- `jiti` (`^2.7.0`) is added to the catalog and to the root `devDependencies`.

## b24ui port
- `docs/nuxt.config.ts`: `import pkg from '../package.json' with { type: 'json' }`,
  ported verbatim. The fork's config has no `./server/utils/llms` or `./site` imports,
  so the `.ts` extension half is n/a.
- `docs/server/utils/llms.ts`: n/a, the file does not exist in the fork.
- `pnpm-workspace.yaml` catalog `jiti: ^2.7.0` and `package.json` devDependency
  `"jiti": "catalog:"`, as upstream.
- `pnpm-lock.yaml`: regenerated with `pnpm install --lockfile-only`. jiti resolves to
  2.7.0, the same as upstream. Hoisting jiti to the root changes the peer suffixes
  of packages that list it as a peer, so the diff is about 300 lines. The set of
  resolved package versions is unchanged; this was checked by comparing the
  package keys before and after.
- `NUXT_B8023` for `src/module` (the extensionless `./templates` import) is not
  addressed upstream either and stays as is.
