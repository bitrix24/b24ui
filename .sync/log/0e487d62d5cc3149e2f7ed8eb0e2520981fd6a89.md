# port — nuxt/ui@0e487d62d5cc3149e2f7ed8eb0e2520981fd6a89

**Upstream:** fix(Table): measure virtualized rows with variable heights (#7204)

**Decision:** port

## Problem
Virtualized rows were forced to `estimateSize` via an inline `height` style and
never measured, so rows with variable content (or an expanded row) overlapped
or left gaps; cached sizes were keyed by index, so they did not follow rows
through sorting/filtering.

## Change
- **src/runtime/components/Table.vue** — rows register with
  `virtualizer.measureElement` via `:ref` and carry the virtualizer's
  `indexAttribute` (default `data-index`); the forced `height` style is dropped
  (row template takes `index` instead of `style`). `getItemKey` defaults to the
  row id (recreated per row set so measurements re-memoize). A wrapping
  `measureElement` adds the expanded `<tr>` height to its row; expanded rows are
  tracked in a `WeakMap`, observed with a `ResizeObserver` and re-measured on
  mount/unmount; observer disconnected in `onBeforeUnmount`.
- **test/components/Table.spec.ts** — three `it.each` tests: index attribute /
  measurement, keys and sizes surviving sorting, expanded-row height.
- **docs/content/docs/2.components/table.md** — tip on measured rows and
  custom `measureElement`.

## Adaptations
- `ui` → `b24ui` (`b24ui.tr`/`b24ui.td`, `props.b24ui?.…`); `import type` kept
  separate. No snapshot changes (no virtualized snapshot cases in the fork).
- Tip added without a `Soon` badge (upstream adds no heading).
