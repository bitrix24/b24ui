# Port: docs(timeline): make the alternating layout example RTL-aware

**Upstream:** `592d5b594bc5f693880207718d0b1fada52ee6d4` (nuxt/ui, #6830)
**Decision:** port — adapted to the fork's prop name

## Upstream change
The alternating-layout Timeline example positions items with negative
translations and a right-aligned text class, none of which flip under RTL:

```diff
-  :ui="{ item: 'even:flex-row-reverse even:-translate-x-[calc(100%-2rem)] even:text-right' }"
-  class="translate-x-[calc(50%-1rem)]"
+  :ui="{ item: 'even:flex-row-reverse even:-translate-x-[calc(100%-2rem)] rtl:even:translate-x-[calc(100%-2rem)] even:text-end' }"
+  class="translate-x-[calc(50%-1rem)] rtl:-translate-x-[calc(50%-1rem)]"
```

Three separate fixes: `text-right` becomes the logical `text-end`, and each
`translate-x` gains an `rtl:` counterpart with the opposite sign, since
`translate-x` is a physical axis that Tailwind does not flip for you.

## b24ui port
Our copy of the example carried the same three defects verbatim. Applied with
the fork's prop name — `:b24ui` rather than `:ui` (§1).

Worth stating why this is not cosmetic here: b24ui ships an `ar` locale with
`dir: 'rtl'`, so the example is reachable in RTL, and under it the even items
would slide the wrong way and align away from their own text.

Also checked the wider class: grep for `rtl:` across
`docs/app/components/content/examples/` previously returned **nothing**, so this
is the first RTL-aware example in the fork's docs. That is a gap rather than a
finding — it means other examples using physical `translate-x`, `text-right` or
`left-`/`right-` may have the same problem. Not swept here, because upstream's
commit is scoped to one example and a blind sweep of the docs would change
layouts nobody has checked in RTL.
