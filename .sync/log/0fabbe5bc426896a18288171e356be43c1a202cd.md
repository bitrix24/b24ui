# Port: fix(theme): keep variants when replacing slot classes in app config

**Upstream:** `0fabbe5bc426896a18288171e356be43c1a202cd` (nuxt/ui, #6824)
**Decision:** port — src verbatim, docs half split three ways

## Upstream change

The slot-class replacer — `(defaults) => classes`, the function form of a slot
value — worked in two places with one implementation, and one of them was wrong.

Before, a replacer in `app.config.<component>` was pulled out of the config at
construction time (`extractDirectives`), the slot blanked, and the replacer
applied at **call time** in `wrapSlots` alongside the `:ui` / `class` ones. That
made it replace the slot's *entire resolved chain* — base **plus variants plus
compound variants**. So setting

```ts
slots: { base: () => 'block w-full' }
```

did not just replace the base classes, it silently discarded every variant class
too: no `bg-primary` from `color`, no padding from `size` (#6800).

The fix splits the two paths, which were never really the same thing:

- **`app.config` replacers resolve at construction time** (`resolveReplacers`).
  The replacer receives the slot's own classes from the extended theme and its
  result takes their place, so `variants` and `compoundVariants` still merge on
  top — exactly as when a plain string is used.
- **`:ui` / `class` replacers stay call-time** in `wrapSlots`, after variant
  resolution, replacing the fully resolved string. `directives` is gone from
  `wrapSlots` entirely.

The mechanism for the first is worth recording because it is not obvious:
`resolveReplacers` **blanks the entry on the `extend` side**. `tv` only ever
concatenates the extended theme into the component's own classes and has no way
to remove them, so blanking the source is the only way to make a replacement.

## b24ui port

**`src/` verbatim.** Confirmed rather than assumed: diffing our
`src/runtime/utils/tv.ts` against upstream's pre-image (after rewriting `b24ui`
→ `ui`) shows the replacer machinery is **line-for-line identical**. The only
differences are this fork's `twMergeConfig` — the `b24-context` / `b24-colors` /
`b24-bg` class groups feeding `createTV` and the `cnMerge` calls — which this
commit does not touch, and one comment we already carry in its post-state.

The upstream patch would not apply as a patch (our `twMergeConfig` shifts
everything by 54 lines and the context carries `b24ui`), so the hunks went in
individually against our exact text.

`src/runtime/types/tv.ts` takes the `SlotClassReplacer` jsDoc rewrite. Our copy
of that file diverges elsewhere — upstream has a `WidenVariantsValues` helper and
a split `compoundVariants` clause we do not — but the commit touches neither.

## Docs half — three different answers

- **`.github/contributing/component-structure.md` (3) and `cli/templates.mjs`
  (2)** — ported, and this is a real fix here rather than a cosmetic follow.
  Upstream's change is `extend: tv(theme)` → `extend: theme`. **All 161
  components in this fork already use `extend: theme`**; these two files were the
  only places still teaching the old form, so the CLI scaffolder was generating
  components in a shape the codebase had abandoned.
- **`docs/…/5.theme/3.components.md`** — n/a, and precisely so. Upstream rewrites
  a sentence in its `app.config.ui` section; **this fork has no such section** —
  the page goes `## Customize theme` → `### b24ui prop` → `### class prop`. The
  replacer sentence we *do* have (line 243) sits under the `b24ui` prop, i.e. the
  call-time path, where the replacer still receives the fully resolved string.
  It remains correct and is left alone. That the `app.config` path is
  undocumented here is #184, and this is another instance of it.
- **`skills/nuxt-ui/references/guidelines/design-system.md`** — absent, and §2
  keeps `skills/` b24ui-authored regardless.

## Tests

Upstream's five new cases, applied with `ui` → `b24ui` in the two test titles
that name the config key.

Proven to do work rather than assumed: reverting **only** `src/` and keeping the
new tests fails three of them —

- `keeps the variants merging on top of a construction-time replacer`
- `passes only the slot own classes to a construction-time replacer`
- `resolves a construction-time replacer when `extend` is a tv result`

— which is the defect the commit exists to fix. The other two pass either way,
as expected: they cover behaviour that was already correct.
