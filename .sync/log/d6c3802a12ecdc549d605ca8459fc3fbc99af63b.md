# Port: fix(Slider): forward aria attributes to the thumb

**Upstream:** `d6c3802a12ecdc549d605ca8459fc3fbc99af63b` (nuxt/ui, #6848)
**Decision:** port — verbatim, against `Range`

## Naming

Upstream's `Slider` is this fork's `Range` (§1, component names). Same reka
primitives underneath — `SliderRoot` / `SliderTrack` / `SliderRange` /
`SliderThumb` keep their own names — so only the wrapper differs. This is the
second commit in that family; `f3c2ac21` (#431) ported
`fix(Slider): bind form aria attributes on thumbs instead of root` and this one
builds directly on it.

## Upstream change

`useFormField`'s derived attributes already reached the thumb after `f3c2ac21`.
What still did not was **the caller's own** `aria-*`: `v-bind="rootProps"` put
them on `SliderRoot`, which is not the element with `role="slider"`. A screen
reader announcing the thumb therefore read Reka UI's placeholder name — `Thumb`
— while the author's `aria-label` sat on a wrapper that announces nothing.

The fix stops inheriting attributes (`inheritAttrs: false`) and routes six of
them by hand:

```
['aria-label', 'aria-labelledby', 'aria-describedby', 'aria-valuetext', 'aria-invalid', 'aria-errormessage']
```

- **One thumb** — the six go to the thumb (`pick`), everything else stays on the
  root (`omit`). `aria-label` falls back to `'Thumb'` only when the caller gave
  neither a label nor a `labelledby`.
- **Several thumbs** — they stay on the root, because Reka UI already names each
  thumb by position (`Minimum`/`Maximum`, or `Value n of m`) and overwriting that
  with one repeated label would make the thumbs indistinguishable. The root then
  takes `role="group"` so the caller's label names the control as a whole —
  unless the caller supplied a `role`, which wins.

## b24ui port

Verbatim. Our `Range.vue` matched upstream's pre-image on both thumb lines and
on the `SliderRoot` binding, so the diff applies unchanged apart from
`ui`→`b24ui` and `UTooltip`→`B24Tooltip`. `pick`/`omit` already exist in
`../utils`.

The docs tip is ported to `range.md` with the component renamed.

## Verify

Ported upstream's 14 `aria` cases and 2 render cases, adapted to `Range`.
Mutation-checked rather than assumed to be meaningful: with `Range.vue` reverted
and the tests kept, **11 of the 14 fail**, plus all 3 affected render cases.

The 3 that pass either way pin behaviour that was already right — the `'Thumb'`
fallback, not grouping an unlabelled range, and leaving non-`aria` attributes on
the root — and are worth keeping as regression pins, but they are not evidence
for this change and are not counted as such.
