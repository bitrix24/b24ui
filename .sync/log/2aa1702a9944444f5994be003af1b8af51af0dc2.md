## Upstream change

Three lines appended to `.github/labeler.yml`:

```yaml
v5:
  - base-branch: 'v5'
```

`actions/labeler` reads this to tag an incoming PR with the major version of the
branch it targets. Upstream keeps one long-lived branch per major — `v2`, `v3`,
`v4` — and is opening `v5`.

## Why it does not apply

**There is no labeler config.** `.github/` holds `ISSUE_TEMPLATE`,
`PULL_REQUEST_TEMPLATE.md`, `contributing`, `dependabot.yml`, `scripts` and
`workflows`, and nothing more. A grep for `labeler` or `base-branch` across the
whole directory returns nothing, so no workflow consumes such a file either.

**And there are no major-version branches to label.** This fork develops on
`main` and ships from it; the sync tracks upstream's `v4` from the outside rather
than mirroring their branch layout. A `v5:` rule here would name a branch that
does not exist and never will under this model.

## Note

Upstream opening `v5` is worth knowing for the sync itself rather than for this
file: the tracked branch in `.sync/nuxt-ui.json` is `v4`, and if upstream's
development moves to `v5` the cursor will stop advancing silently rather than
loudly. Nothing to do yet — `v4` is still where these commits land — but it is the
kind of change that ends a sync without an error.
