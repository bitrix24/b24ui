# port — nuxt/ui@90c45a66e6f69855980ace5e162af61629eb929e

**Upstream:** fix(Checkbox/RadioGroup): add `flex-wrap` on `list` and `card` variants (#6913)

**Decision:** port.

Second of two contiguous commits taken in one PR (§6 4b), after `bbf1e149`.

## Upstream change

`fieldset` lays the options out with `flex`, and in the horizontal orientation a
row of them simply overflowed its container — no wrapping, so options past the
edge were unreachable. One class on each of two variants:

```diff
-      list: {},
-      card: {},
+      list: { fieldset: 'flex-wrap' },
+      card: { fieldset: 'flex-wrap' },
```

The `table` variant is deliberately left out on both sides: its rows are seamed
together with `-space-x-px` and `-space-y-px`, and wrapping would break the seam
rather than fix an overflow.

## b24ui port

Same two variants, same slot, same class. One shape difference: upstream's `card`
was an empty object, so it gains a single key; ours already carries `item`
styling, so `fieldset: 'flex-wrap'` goes in as the first entry alongside it.
`list` was `{}` here too (`{ }` in `radio-group.ts`).

**The fix is worth more here than upstream, and that is checkable rather than a
claim.** Our `fieldset` already declares a *vertical* gap at every size —
`gap-x-[12px] gap-y-[4px]` at the smallest through `gap-x-[16px] gap-y-2` at the
largest, in both files. A `gap-y` on a non-wrapping single-line flex row is
inert: it can only take effect once the row wraps. So the theme was already
written for wrapped rows and the property that produces them was missing.

## Snapshots

126 lines across four files, and the movement was checked rather than accepted:
matching each `-`/`+` pair and extracting the differing substring gives
**insertions only**, all of them the `flex-wrap` token, with no deletions at all.
The set of attribute *names* in both snapshot files is identical before and
after, which is the check a per-line diff cannot do — a class dropped from every
element at once would otherwise read as ordinary churn.

Ours moves 126 lines against upstream's 148 because this fork has fewer size
variants covered by the `list`/`card` cases.
