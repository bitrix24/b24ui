# Port: fix(Link): promote queued prefetch on interaction (#7124)

**Upstream:** `974cc0d9fa22a45e450e3171c3d9024275c4ec75` (nuxt/ui)
**Decision:** port

## Upstream change
Since Nuxt 4.6, prefetch work is queued, and NuxtLink moves a link's queued work to the
front when the user reaches for it. It does this only for non-custom links, and Link always
renders NuxtLink with `custom`. So Link now does it itself:
- After a link has prefetched, `pointerenter`, `focus` and the new `pointerdown` call
  `nuxtApp._prefetch.promote(pathname + search)`. This is the same key NuxtLink uses.
- Before that, interaction mode still prefetches on those events, as it did before.
- `prefetchApi` now also carries `prefetched` and the route's `fullPath` (none for
  external links), and `getPrefetchListeners` takes `linkRoute`.
- A comment in the visibility hook now says that the `onNuxtReady` wait matters
  only before Nuxt 4.6.
- `LinkPrefetch.spec.ts` gets a new case: promotion happens on all three events, only
  once the link has prefetched, and with the hash stripped.
