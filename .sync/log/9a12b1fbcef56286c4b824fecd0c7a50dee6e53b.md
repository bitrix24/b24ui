# Port: fix(ColorModeButton): resolve label after mount (#7167)

**Upstream:** `9a12b1fbcef56286c4b824fecd0c7a50dee6e53b` (nuxt/ui)
**Decision:** port

## Upstream change
`ColorModeButton`'s `isDark` getter read `colorMode.value === 'dark'` directly. The
resolved color mode is only known on the client, so in SSR the server rendered the
"Switch to dark mode" `aria-label` while a dark-mode client hydrated with "Switch to light
mode". The result was a hydration mismatch, and the label could stay stale. The getter is
now `mounted.value && colorMode.value === 'dark'`, with `useMounted()` from `@vueuse/core`.
The label matches the server until mount and then updates. A new spec renders the button
with `renderToString`, hydrates it, and asserts that there is no hydration warning and the
label is correct after mount.

## b24ui port
- `src/runtime/components/color-mode/ColorModeButton.vue`: adds `useMounted` to the
  `@vueuse/core` import, adds the `mounted` ref with upstream's comment, and guards the
  getter. This is verbatim. The fork's differences are kept: the `air-tertiary-no-accent`
  default, `useComponentProps('button', …)`, and the b24-icons leading slot. The setter is
  unchanged.
- The fork has no Vue-specific override of `ColorModeButton` (`src/runtime/vue/components/color-mode/`
  holds only Select and Switch), so there is no second copy to patch. `ColorModeSwitch` /
  `ColorModeSelect` are untouched, as upstream leaves them.

## Tests
- `test/components/color-mode/ColorModeButton.spec.ts`: new, verbatim from upstream. The
  locale strings (`Switch to dark mode` / `Switch to light mode`) match the fork's `en`
  locale. The spec installs its own `console.warn` spy inside the test body, so the
  console gate does not see it and it needs no `KNOWN_NOISY_SPECS` entry. It is collected
  by both the `nuxt` and the `vue` projects (`components/**`).
- No snapshot files change: before mount, the label is the one the old code produced for
  light mode, which is the test environment's mode.

## Verify (CI=true)

## Test adaptation (orchestrator)
The fork's `useColorMode` (`src/runtime/composables/color-mode/useColorMode.ts`) returns a `{ forced: true }` stub with no `value` when `appConfig.colorMode` is off, which it is in the Nuxt test project, so upstream's spec failed there (`colorMode.value` was `undefined`, the label never flipped). The spec now `vi.mock`s that composable with a plain reactive store; the assertions are upstream's, unchanged. Passes in both the `nuxt` and `vue` projects.
