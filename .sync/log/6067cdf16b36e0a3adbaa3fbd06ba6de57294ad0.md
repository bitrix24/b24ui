# Port: docs(server): trim navigation payload (#7159)

**Upstream:** `6067cdf16b36e0a3adbaa3fbd06ba6de57294ad0` (nuxt/ui)
**Decision:** port

## Upstream change
`/api/navigation.json` is pre-rendered, fetched by `app.vue` and `error.vue`, and its
tree lands in the payload of every docs page. `queryCollectionNavigation` returns every
requested field as `null` on the pages that do not set it, and it adds a `stem` to every
item. Upstream trims both:
- `docs/server/api/navigation.json.get.ts`: a recursive `compact()` drops `stem` and
  every `null`-valued field, and recurses into `children`. The handler becomes `async`
  and returns `compact(await queryCollectionNavigation(…))`. The comment explains that
  `stem` is only read by `findPageHeadline` without `indexAsChild`.
- `docs/app/app.vue`, `docs/app/error.vue`: `useFetch<ContentNavigationItem[]>(…)` with
  a `import type { ContentNavigationItem } from '@nuxt/content'`. The handler's
  inferred return type no longer carries the nav item shape.

## b24ui port
The fork has all three files. Its `navigation.json.get.ts` differs from upstream's
pre-image in two ways, and both are kept:
- **Field list.** The fork requests `['framework', 'category', 'description']`. It does
  not request `'to', 'target'`: those belong to upstream's docs-schema addition, recorded
  n/a in nuxt/ui@6b4d2c7.
- **A commented-out `useAsyncData` line**, which stays above the handler.

Applied:
- `docs/server/api/navigation.json.get.ts`: `compact()` and its comment verbatim, and the
  handler made `async` and wrapped in `compact()`, over the fork's field list.
- `docs/app/app.vue`, `docs/app/error.vue`: the type import and `useFetch` generic,
  verbatim. In `app.vue` the import sits next to the fork's existing
  `import type { ToasterProps }`.

The comment's claim was checked against the fork rather than assumed:
- `docs/app` never calls `findPageHeadline`. It uses `findPageChildren` and
  `findPageBreadcrumb` (both with `indexAsChild: true`) in `useNavigation.ts`, and per
  `@nuxt/content@3.16.1`'s `dist/runtime/utils` neither reads `stem`. The only `stem`
  reads (`[...slug]/index.vue`, `page-links.md`) are on the page document, not on nav
  items.
- No consumer of the injected `navigation` compares a nav field with `null`. The fork's
  `useNavigation.ts` tests `item.category`, `child.framework` and `item.framework` for
  truthiness only, so `null` becoming absent changes nothing.
