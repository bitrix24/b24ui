# Port: fix(Theme): merge `class` from `props` with the component class

**Upstream:** `731ff26bf9adb861e7458cd47664bcb7c086705f` (nuxt/ui, #6842)
**Decision:** port — verbatim, one identifier renamed

## Upstream change

`useComponentProps` already treated `ui` specially: a theme's slot classes are
**merged** with the component's, not replaced by them. Every other prop takes
the ordinary "explicit wins outright" path — which is right for `size` or
`color`, and wrong for `class`.

The consequence: `<UTheme :props="{ button: { class: 'rounded-full' } }">` had
no effect on any Button that set a `class` of its own. The theme class was not
overridden by a conflicting one, which would be reasonable — it was dropped
whole, so `class="hidden"` on a button silently discarded `rounded-full` too.

```ts
if (prop === 'class') {
  const themeClass = themeEntry?.class
  if (themeClass === undefined) return raw
  if (raw === undefined) return themeClass
  return [themeClass, raw]
}
```

The order is the whole point: theme first, explicit last, so `twMerge` resolves
a genuine conflict in favour of the explicit class while non-conflicting classes
from both survive.

## b24ui port

Verbatim. Our `useComponentProps.ts` has the identical shape — the special-case
branch (`b24ui` here, `ui` upstream) sits in the same place, immediately before
the `propIsDefined` early return, and the new branch goes directly after it.

The only edit is the jsDoc line, which names the prop: `ui` → `b24ui`.

Worth noting for the next porter that the placement matters and is not obvious
from the diff. The branch must come **before** `if (vm && propIsDefined(vm.vnode, prop)) return raw`.
That guard is what implements "an explicitly-passed prop wins", and `class` on a
component is always explicitly passed — so behind the guard the new branch would
be unreachable and the fix would be a no-op that still typechecks and still
reads correctly.

## Tests

Upstream's two cases, applied unchanged; this fork's `Button` has no `rounded-*`
in its base classes, so `rounded-full` / `rounded-none` discriminate here exactly
as they do upstream.

They are not redundant, which mutation testing confirms rather than assumes:

- deleting the branch fails **`:props class merges with an explicit class`**
  only — the override case still passes, because with the branch gone the
  explicit class wins by default;
- reversing the array to `[raw, themeClass]` fails **`:props class is overridden
  by a conflicting explicit class`** only — merging still happens, `twMerge` just
  resolves the conflict the wrong way.

So each test pins one half, and neither would have caught the other's defect.
