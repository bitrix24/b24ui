## Upstream change

A single `::tip` block added to the design-system page, saying that Tailwind CSS
v4's Preflight gives buttons `cursor: default` instead of `cursor: pointer`, and
showing the `@layer base` rule that restores the pointer globally:

```css [app/assets/css/main.css]
@layer base {
  button:not(:disabled),
  [role="button"]:not(:disabled) {
    cursor: pointer;
  }
}
```

Documentation only — no `src` change on either side.

## b24ui port

The tip is ported **byte for byte**, including the code-fence label. That is
correct rather than lazy: the snippet is a rule the *consumer* adds to their own
application's stylesheet, and `app/assets/css/main.css` is the Nuxt convention
for it, not a path inside this repository. Nothing in it is Nuxt-UI-specific —
no `ui`/`b24ui` token, no component name, no import — so there was nothing to
rewrite.

The one difference is the insertion point, and it is a consequence of the pages
having diverged rather than a decision. Both files anchor the tip after the same
paragraph ("Check the Tailwind CSS documentation for all available theme variable
customization options."), but the heading that follows differs — `### Fonts`
upstream, `### Breakpoints` here — because this fork's design-system page orders
its sections differently. Same anchor, same position relative to it.
