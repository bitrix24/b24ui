## b24ui port

### The two pins matter more here than upstream
Both are load-bearing for this fork *today*, not hypothetically:

- **`tailwind-variants: 3.2.2`** — b24ui declares `^3.2.2` and npm already
  publishes **3.3.1**, so the next lockfile regeneration floats there on its
  own. 3.3.x is a full internal rewrite: invoking a `tv()` result is 18–103×
  slower (`test/bench/tv.bench.ts` measures exactly this) and the exported type
  constraints changed in a breaking way. This module calls `tv()` on every
  component render, so the regression would land on consumers, not just CI.
- **`@nuxt/image: 2.0.0`** — b24ui `docs` declares `^2.0.0` and npm publishes
  **2.1.0**, which depends on `ipx@4.0.0-beta.1` and pulls a second sharp
  alongside 0.34.5, killing the docs prerender on `/_ipx`. The docs site is
  built by `deploy.yml`, which the `ci` gate never runs — so this would have
  surfaced in production, not in a PR.

### `vite` 8.2.1 vs the fork's `rolldown` override
Upstream moved `playgrounds/{repl,vue}` to `vite ^8.2.1`. b24ui carries two
fork-only overrides added during the `282759e` port — `vite: ^8.1.5` and
`rolldown: ~1.1.5` — because two vite copies mean two rolldown native ABIs in
one process, which breaks vitest's pool with ``Missing field `moduleType` ``.

`vite@8.2.1` depends on `rolldown ~1.2.1`, and the old `vite: ^8.1.5` override
already *permitted* 8.2.1 — so a regeneration would have paired vite 8.2.1 with
a rolldown pinned back to 1.1.5: the same ABI split, in the other direction.
Both overrides move together: `vite: ^8.2.1`, `rolldown: ~1.2.1` (resolves
1.2.3), and the comment now spells out that the two must stay in step.
Verified single-copy after install: `vite 8.2.1`, `rolldown 1.2.3`.

### `@comark/vue` 0.5.x → 0.6.2 (breaking rename)
Applied across all seven fork call sites, mirroring upstream's own edit:

- `docs/app/components/chat/Comark.client.ts` → **`Markdown.client.ts`**
  (`defineMarkdownComponent`, `name: 'ChatMarkdown'`, `shiki()` plugin);
- `docs/app/components/chat/Chat.vue` — `<ChatComark>` → `<ChatMarkdown>`,
  `:markdown` → `:value`;
- `docs/app/components/content/examples/chat/ChatPaletteContentSearchExample.vue`,
  `.../chat/ChatPaletteModalExample.vue`,
  `.../sidebar/SidebarChatExample.vue` — `Comark` → `Markdown`,
  `highlight()` → `shiki()`;
- `playgrounds/nuxt/app/pages/chat.vue` — same;
- `optimizeDeps.include` in `docs/nuxt.config.ts`,
  `playgrounds/nuxt/nuxt.config.ts` and the fork-only
  `playgrounds/demo/nuxt.config.ts` — `plugins/highlight` → `plugins/shiki`.

**The shiki stack had to move with it.** `comark@0.6.2` declares
`shiki: ^4.3.1` as an (optional) peer, and `plugins/shiki` is not optional for
us once imported. `docs` sat on `shiki ^4.2.0` with `@shikijs/{core,
engine-javascript, langs, themes} ^4.0.2`, and the first install left the peer
unmet (`Installed: 4.2.0 / Wanted: ^4.3.1`). Those five ranges plus the
already-bumped `@shikijs/types` now all read `^4.4.2` (resolves 4.4.3), which
satisfies the peer and keeps `docs/app/mdc.config.ts`'s
`ShikiTransformer` cast against the same major.minor as the runtime.
`tiptap-extension-code-block-shiki` accepts `^3 || ^4`, so it is unaffected.
`pnpm peers check` reports no shiki entry afterwards.

### Carried source fixes
- **`src/runtime/types/html.ts`** — `ImgHTMLAttributes` no longer `Pick`s
  `crossorigin` from Vue; it is re-declared as
  `'anonymous' | 'use-credentials'` so the type stays assignable to `NuxtImg`,
  which rejects `''`. b24ui's file was byte-identical to upstream's
  pre-change version — applied verbatim, comment included.
- **`docs/app/components/content/ComponentPropsSchema.vue`** — `getSchemaProps`
  gains `!('schema' in schema)`; vue-component-meta 3.3.9 widens
  `PropertyMeta['schema']` to a union whose members do not all carry `schema`.
  Also byte-identical before the change.

## Verify (CI=true)
`dev:prepare` · `lint` · `test` · `typecheck` · `build` — all green.
`docs:generate` run out-of-band as well, because the `ci` gate never builds the
docs site and this commit rewrites six docs components plus the shiki stack
they render through: **`Prerendered 1240 routes`, exit 0** — the same route
count as the last out-of-band run (`3a19e23`).

One trap worth recording: the first attempt failed with
`[404] Page not found: /releases`. That is not a regression — `docs/nuxt.config.ts`
reads `NUXT_PUBLIC_GIT_URL` with `?? ''`, so without it `Footer.vue`'s
`` `${config.public.gitUrl}/releases` `` collapses to a *relative* `/releases`,
which the prerender crawler follows as an internal route and cannot match.
`deploy.yml` sets that variable; the run has to be given the same env to mean
anything.
