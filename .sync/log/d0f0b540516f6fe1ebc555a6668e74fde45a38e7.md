# Port: docs: reduce heap used by the server bundle (#7097)

**Upstream:** `d0f0b540516f6fe1ebc555a6668e74fde45a38e7` (nuxt/ui)
**Decision:** port — partial

## Upstream change
Three changes to the docs build, each aimed at heap used while Nitro bundles
the server:
1. `$production.sourcemap.server = false` in `docs/nuxt.config.ts`.
2. `icon.serverBundle.externalizeIconsJson = true`, so `@nuxt/icon` keeps the
   collections as JSON files instead of inlining them into the bundle.
3. `docs/server/utils/transformMDC.ts` imports component meta from
   `#nuxt-component-meta/nitro`, the alias that nuxt-component-meta's own
   `/api/component-meta` route already imports, so the meta is bundled once.

## b24ui port
- (1) Ported. Our docs config had no `$production` block, so one is added after
  `site`, with only `sourcemap.server: false`. The upstream `site.url` inside
  it does not apply: our site URL comes from `NUXT_PUBLIC_SITE_URL`.
- (3) Ported verbatim. nuxt-component-meta 0.18.0 registers the same
  `#nuxt-component-meta/nitro` virtual module, and its route handler imports it.
- (2) n/a. The docs site does not use `@nuxt/icon` (it uses
  `@bitrix24/b24icons-vue`), and `docs/nuxt.config.ts` has no `icon:` key.
